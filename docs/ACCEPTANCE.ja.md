# コンピューターの最終確認

[English](ACCEPTANCE.md)

[Documentation](README.ja.md) · [Build/release procedure](RELEASING.ja.md)

<a id="obtain-the-exact-build"></a>
## 正確なビルドの取得

1. レポジトリのデフォルトブランチにレビュー済みの変更をプッシュします。
2. **Actions → Build release → Run workflow**を実行します。
3. 成功した実行の**release-bundle**アーティファクトをダウンロードします。
4. `build-manifest.json`から実行ID、コミットSHA、バージョンを記録します。
5. 各コンピューターで、その`public`ディレクトリから一致するパッケージをインストールします。

このパブリックリポジトリ内のビルドアーティファクトはリポジトリの閲覧者に表示されます。ダウンロードにはGitHubへのサインインが必要です。これらは承認済みの開発ビルドであり、公開されたリリースではありません。
アーティファクトは30日後に有効期限が切れます。テスト中はローカルコピーを保持してください。
ビルド内のインストールスクリプトは、そのバージョンが公開されるまで機能しないリリースURLを指しています。この段階では、ダウンロードしたEXE/DMG/DEB/RPMを直接テストしてください。

Python、Node.js、Git、FFmpeg、MediaMTXがインストールされていないクリーンなアカウント/VMを使用してください。
テスト用カメラと使い捨ての録画用フォルダーを使用してください。容量/保持期間のチェックにより、対象となるテスト録画が意図的に削除されます。

<a id="target-matrix"></a>
## ターゲットマトリックス

**pass**（合格）、**fail**（不合格）、**not tested**（未テスト）を個別に記録してください。ビルドの成功はOSを保証するものではありません。

| OS | CPU | インストール/セットアップ | ライブ/録画/再生 | アップデート/データ保持 |
| --- | --- | --- | --- | --- |
| Windows 10 22H2 / Windows 11 | x64 | | | |
| Windows 10 22H2 / Windows 11 | ARM64 | | | |
| macOS 14+ | Intel | | | |
| macOS 14+ | Apple Silicon | | | |
| Ubuntu 24.04 | x64 / ARM64 | | | |
| Rocky Linux 9 / 10 | x64 / ARM64 | | | |
| Raspberry Pi OS Bookworm, 64-bit, Pi 4/5 | ARM64 | | | |
| Docker Engine on Linux | amd64 / arm64 | | | |

一部のターゲットがテストされていない場合は、完全なマトリックスが検証済みであると宣伝するのではなく、開発プレビューとしてビルドを維持してください。
実際のRaspberry Piのカメラ台数/解像度/fpsを記録してください。普遍的なカメラの制限を外挿しないでください。

<a id="desktop-checklist"></a>
## デスクトップチェックリスト

- [ ] インストーラーが開発者ツールなしで動作する。署名なしアプリの確認はドキュメント化されたOSの手順に従う。
- [ ] 管理者パスワードの作成、キャンセル、再開が機能する。デフォルトパスワードによるアクセス許可はない。
- [ ] 初回起動時の英語ツアーが開き、スキップと再開が機能する。
- [ ] USBの権限と検出が機能する。IPカメラがその認証情報を使用して接続できる。
- [ ] ライブビュー、カメラ録画、録画一覧、ダウンロード、再生が機能する。
- [ ] macOSでは、DMGからアプリをコピーし、DMGを取り出し、終了/再起動を行い、MediaMTXとUSBカメラが稼働し続けることを確認する。停止したアプリを移動し、同じプロファイルで再起動し、録画/設定が引き続き利用可能であることを確認する。置換アプリのインストール後、ログイン時の自動起動を繰り返す。
- [ ] ビューアーアクセスには設定されたビューアーパスワードが必要であり、設定を変更できない。
- [ ] 初期ストレージの推奨値は min(50 GB, 空き容量の半分) であり、保持期間は7日である。
- [ ] 年齢ベースおよび容量ベースの両方のクリーンアップにより、完了した対象のテスト録画のみが削除される。
- [ ] フォルダーの変更により、古い録画がデフォルトで表示されたままになる。オプションをオフにすると非表示になる。
- [ ] 削除/再接続されたディスクや空き容量不足により、理解しやすい動作が発生する。
- [ ] 非ASCIIユーザー名、スペースを含むパス、カスタム録画フォルダーが機能する。
- [ ] ブラウザーを閉じてもモニタリングが継続し、明示的な終了によって停止し、重複起動によって2つのサーバーが作成されない。
- [ ] ログイン時の自動起動が機能し、手動でのスリープ/ログアウト/シャットダウンの動作が理解されている。
- [ ] アップグレードにより設定と録画が保持され、通常のアンインストールによりデータが保持される。Windowsでは、APIがアクティブな間にアンインストールする。API/メディアプロセスが停止し、バンドルされた実行ファイルが削除されることを確認する。macOSでは、トレイ/コントロールウィンドウとDockから個別に終了する。カメラがオフになり、所有されているメディアプロセスが終了することを確認する。
- [ ] LAN視聴にはHTTPSを使用し、認証が必要である。内部メディアエンドポイントを匿名で使用することはできない。

<a id="server-checklist"></a>
## サーバーチェックリスト

- [ ] DockerがUID/GID 10001として起動し、コンテナーの再作成後もデータを保持する。
- [ ] ヘッドレス初回起動トークンはプライベートであり、使い捨てであり、ログに記録されない。
- [ ] 固定バージョンを使用したComposeのpull/updateおよびロールバックが機能する。
- [ ] systemdがデスクトップログインなしで独自のアカウント/データディレクトリを使用して起動する。
- [ ] どちらのデプロイメントも、デスクトップインスタンスとポートまたはライブデータディレクトリを共有しない。

<a id="publication-sign-off"></a>
## 公開の承認

ソース/ライセンスアーカイブ、インストーラーインベントリ、チェックサムをレビューする。
ソースコミットとビルド実行 IDがテストしたものと正確に一致していることを確認する。
承認後にパッケージを編集/再ビルドしない。コードの変更には、新しいビルドと適切な再チェックが必要となる。

ソースリポジトリはすでに公開されている。このレビューの後でのみ、一致するパブリックプレビューフラグを有効にし、**Publish tested release**の両方のフェーズを使用する。最初のパブリックプレビューには、カメラの録画/再生、完全なGUI終了、データ保持付きのWindowsアンインストールを含め、Windows x64、M1 Mac、Linux x64デバイスの合格が必要である。該当する場合は、他のプラットフォームを未テストとしてマークする。パブリックプレビューではGitHub Pre-releaseを使用し、Latestは絶対に使用しない。
公開後、クリーンなコンピューターからのREADMEのワンコマンドインストールルートを検証し、宣伝されているすべてのリリースアセットにアクセスできることを確認する。
