# コンピューターでの最終確認

[English](ACCEPTANCE.md)

<a id="obtain-the-exact-build"></a>
## 正確なビルドの取得

1. レポジトリのデフォルトブランチにレビュー済みの変更をプッシュします。
2. **Actions → Build release → Run workflow** を実行します。
3. 成功した実行の **release-bundle** アーティファクトをダウンロードします。
4. `build-manifest.json` からその実行 ID、コミット SHA、およびバージョンを記録します。
5. 各コンピューターで、`public` ディレクトリから一致するパッケージをインストールします。

このパブリックリポジトリ内のビルドアーティファクトはリポジトリの閲覧者に公開されており、ダウンロードには GitHub へのサインインが必要です。これらは公開されたリリースではなく、未承認の開発ビルドです。
アーティファクトは 30 日後に期限切れになります。テスト中はローカルコピーを保管してください。
ビルド内のインストールスクリプトは、そのバージョンが公開されるまで機能しないリリース URL を指しています。この段階では、ダウンロードした EXE/DMG/DEB/RPM を直接テストしてください。

Python、Node.js、Git、FFmpeg、MediaMTX がインストールされていないクリーンなアカウント/VMを使用してください。
テストカメラと使い捨ての録画フォルダーを使用します。容量/保持期間の確認によって、対象となるテスト録画が意図的に削除されるためです。

<a id="target-matrix"></a>
## ターゲットマトリックス

**pass**（合格）、**fail**（不合格）、または **not tested**（未テスト）を個別に記録します。ビルドの成功は OS を認定するものではありません。

| OS | CPU | インストール/設定 | ライブ/録画/再生 | アップデート/データ保持 |
| --- | --- | --- | --- | --- |
| Windows 10 22H2 / Windows 11 | x64 | | | |
| Windows 10 22H2 / Windows 11 | ARM64 | | | |
| macOS 14+ | Intel | | | |
| macOS 14+ | Apple Silicon | | | |
| Ubuntu 24.04 | x64 / ARM64 | | | |
| Rocky Linux 9 / 10 | x64 / ARM64 | | | |
| Raspberry Pi OS Bookworm, 64-bit, Pi 4/5 | ARM64 | | | |
| Linux上の Docker Engine | amd64 / arm64 | | | |

一部のターゲットがテストされていない場合は、検証済みの全マトリックスとして宣伝するのではなく、ビルドを開発プレビューとして維持してください。
実際の Raspberry Pi のカメラ台数/解像度/fps を記録し、一般的なカメラの制限を外挿しないでください。

<a id="desktop-checklist"></a>
## デスクトップチェックリスト

- [ ] インストーラーが開発ツールなしで動作する。未署名アプリの確認はドキュメント化された OS のフローに従う。
- [ ] 管理者パスワードの作成、キャンセル、再開が機能し、デフォルトパスワードでアクセスできない。
- [ ] 初回起動時の英語ツアーが開き、スキップと再オープンが機能する。
- [ ] USB の権限と検出が機能し、IP カメラがその資格情報を使用して接続できる。
- [ ] ライブビュー、カメラ録画、録画リスト、ダウンロード、再生が機能する。
- [ ] macOS では、DMG からアプリをコピーし、DMG を取り出し、終了/再起動を行い、MediaMTX と USB カメラが実行状態を維持することを確認する。停止したアプリを移動し、同じプロファイルで再起動し、録画/設定が引き続き利用可能であることを確認する。代替アプリのインストール後、ログイン時自動起動を再度確認する。
- [ ] ビューアーアクセスには設定されたビューアーパスワードが必要であり、設定を変更できない。
- [ ] 初期ストレージの提案は min(50 GB, 空き容量の半分) であり、保持期間は 7 日間である。
- [ ] 経過時間ベースと容量ベースの両方のクリーンアップにより、完了した対象テスト録画のみが削除される。
- [ ] フォルダーの変更により古い録画がデフォルトで表示されたままになり、オプションをオフにすると非表示になる。
- [ ] 削除/再接続されたディスクや空き容量不足により、理解しやすい動作が生成される。
- [ ] 非 ASCII ユーザー名、スペースを含むパス、カスタム録画フォルダーが機能する。
- [ ] ブラウザーを閉じても監視が継続し、明示的な終了によって停止し、二重起動によって 2 つのサーバーが作成されない。
- [ ] ログイン時自動起動が機能し、手動でのスリープ/ログアウト/シャットダウンの動作が理解されている。
- [ ] アップグレードにより設定と録画が保持され、通常のアンインストールによりデータが保持される。Windows では、API がアクティブな状態でアンインストールする。API/メディアプロセスが停止し、バンドルされた実行ファイルが削除されることを確認する。macOS では、トレイ/コントロールウィンドウと Dock から別々に終了する。カメラがオフになり、所有されているメディアプロセスが終了することを確認する。
- [ ] LAN 視聴では HTTPS が使用され、認証が必要である。内部メディアエンドポイントを匿名で使用することはできない。

<a id="server-checklist"></a>
## サーバーチェックリスト

- [ ] Docker が UID/GID 10001 として起動し、コンテナの再作成後もデータを保持する。
- [ ] ヘッドレスの初回起動トークンがプライベートかつ 1 回限りであり、ログに記録されない。
- [ ] 固定バージョンを使用して、Compose のプル/アップデートおよびロールバックが機能する。
- [ ] systemd が独自のアカウント/データディレクトリを使用してデスクトップログインなしで起動する。
- [ ] どちらのデプロイメントも、ポートやライブデータディレクトリをデスクトップインスタンスと共有しない。

<a id="publication-sign-off"></a>
## 公開の承認 (Publication sign-off)

ソース/ライセンスアーカイブ、インストーラーインベントリ、チェックサムを確認します。
ソースコミットとビルド実行 ID が、テストした内容と正確に一致していることを確認します。
承認後にパッケージを編集/再ビルドしないでください。コードの変更には、新しいビルドと適切な再確認が必要です。

ソースリポジトリはすでに公開されています。このレビューの後でのみ、対応する公開プレビューフラグを有効にし、**Publish tested release** の両方のフェーズを使用してください。最初の公開プレビューには、カメラの録画/再生、GUI の完全な終了、データ保持付きの Windows アンインストールなど、Windows x64、M1 Mac、および Linux x64 デバイスの合格が必要です。該当する場合は、他のプラットフォームを未テストとしてマークしてください。公開プレビューでは GitHub の Pre-release を使用し、Latest は絶対に使用しないでください。
公開後、クリーンなコンピューターからの README のワンコマンドインストールルートを確認し、宣伝されているすべてのリリースアセットにアクセスできることを確認します。
