# コミュニティ配布

[English](DISTRIBUTION.md)

<a id="user-installation"></a>
## ユーザーインストール

デスクトップパッケージには、Python、コンパイル済みのWeb UI、FFmpeg、MediaMTXが含まれています。
ユーザーがPython、Node.js、npm、Dockerをインストールする必要はありません。

Windowsでは、対応する `FlintEye-<version>-windows-<arch>-setup.exe` を実行します。アプリケーションファイルをコピーした後、セットアップによってネイティブウィンドウが開きます。
`admin` パスワードを設定します（12〜1024文字、2回入力）。パスワードは
ローカルでハッシュ化され、インストーラーの引数やログに含まれることはありません。パスワードを入力せずにセットアップを閉じると
セットアップは保留状態になり、次回の起動時に再開されます。

macOSでは、DMGから `FlintEye.app` を「アプリケーション」フォルダにコピーして開きます。Linuxでは、
デスクトップパッケージインストーラーを使用してDEB/RPMをインストールし、FlintEyeを開きます。初回起動時に同じ
パスワード入力ウィンドウが表示されます。このコミュニティ版には、Developer ID署名/公証および
Windowsのパブリッシャー署名は含まれていません。macOSでは、アプリ固有の **プライバシーとセキュリティ → このまま開く** 操作が
必要な場合があります。OS全体のセキュリティを無効にしないでください。macOSのバンドルは、ARM64用のローカルなアドホック整合性署名を使用しています。

セットアップ完了後にブラウザが開きます。英語の入門ガイドは
スキップして後から再度開くことができます。USB/IPカメラは「設定」で設定します。
`viewer` パスワードは **設定 → ランタイムとアクセス → ビューアーアクセス** で
設定します。そのパスワードが存在するまで、ビューアーはサインインできません。
変更すると、既存のセッションが無効になります。

設定インターフェースは、Windows、macOS、Linux、Docker、およびソースからのインストールで共有されます。録画の保存場所、クォータ、保持期間は **設定 → 録画** にあり、
アップデートの確認は **設定 → 一般** にあります。古いインストーラーは、再構築して再インストールされるまで、埋め込みインターフェースを維持します。ローカルのApple Siliconビルドについては、[DMGビルドガイド](LOCAL_MACOS_BUILD.ja.md)に従ってください。

ブラウザを閉じても監視は実行されたままになります。Windows/macOSでは、トレイメニューから **FlintEyeを開く**、ログの表示、**監視を停止して終了** を利用できます。
Linuxでは、トレイ拡張機能が不要な小さなコントロールウィンドウを使用します。
現在のデスクトップユーザーに対してログイン時の自動起動がインストールされます。
デスクトップアプリケーションの実行中は自動スリープが抑制されます。手動でのスリープ/ログアウト/シャットダウンを行うと監視が中断されます。
Linuxでの抑制には、動作中のsystemd/logindセッションが必要です。

FlintEyeはデフォルトで `http://127.0.0.1:18080` でローカル接続を受け入れます。
他のLANデバイスからのアクセスのためには、そのループバックエンドポイントの前段にHTTPSリバースプロキシを配置し、
`/api` と `/media` をWebSocketサポート付きでプロキシしてください。
MediaMTXのHTTP、RTSP、管理リスナーはループバック上に維持してください。平文のHTTPポートをLANに公開しないでください。
ローカルプロキシは `X-Forwarded-Proto: https` を設定し、外部のHostヘッダーを保持する必要があります。
転送されたヘッダーは、`127.0.0.1` および `::1` からのもののみが信頼されます。
インストールホストとビューアーデバイス間のWebRTCメディア用に、UDP 8189を許可してください。

<a id="recording-lifecycle"></a>
## 録画のライフサイクル

デフォルトの保持期間は7日間です。初期クォータは、50 GB（十進法）と
選択したフォルダの利用可能バイト数の半分とのうち小さい方になります。この提案値は保存されるものであり、
継続的にサイズ変更されるわけではありません。ユーザーはクォータを変更できます。ストレージの選択はインストールPC上でネイティブに行われます。\リモート管理者は絶対サーバーパスを入力します。

どちらかの制限に達すると、最も古い完了済みの録画が
削除されます。7日間というのは最大値であり、保証ではありません。完了フックは
セグメントをSQLiteインベントリに登録します。サイズとmtimeが依然として一致する、
登録されたファイルのみがFlintEyeによって削除されます。アクティブ/未登録/インポート済みのファイルは
削除されません。このモードでは、MediaMTXの独立した有効期限による削除が無効になります。
再生コピーは、録画フォルダ外のプライベートで制限された一時キャッシュを使用するようになりました。
`recording.playback_cache_max_bytes` のデフォルトは 2 GB であり、より大きなセグメントのために
詳細なJSONで増やすことができます。キャッシュへの書き込みでは、設定された空き容量の予備に加えて256 MBが保持されます。収まらないセグメントは
再生の対象外となります。元の録画は管理者がダウンロードできるように保持されます。
録画フォルダ内で `.playback_cache` を使用していた開発版をアップグレードする前に、
FlintEyeを停止し、その古いキャッシュディレクトリを削除してください。
アクティブなフォルダが消失した場合、またはクリーンアップ後も空き容量が1 GB未満のままである場合は、
録画が一時停止され、バナーが表示されます。条件が解消されると再開されます。
クォータの適用は30秒ごとに実行され、アクティブなセグメントによる一時的な超過を許可します。
十分なディスクの余裕を持たせてください。インポート済み/未登録のファイルでは手動のクリーンアップが必要になる場合があります。完了フックの前にクラッシュが発生すると、そのようなファイルが残る可能性があります。

録画フォルダを変更しても、録画は移動されません。古いフォルダには独自の以前の保持/クォータ設定が維持されます。
デフォルトでは表示されたままになります。
**以前の場所からの録画を表示する** を無効にすると、それらの再生エンドポイントとリストエントリは非表示になりますが、保持は停止されません。
異なるルートにある同じファイル名は、異なる録画IDを持ちます。
ディスクを外すとその録画は利用できなくなります。再度アクセスするには接続し直してください。

設定、インベントリ、ログ、録画はインストールディレクトリの外に保存されます：

* Windows：`%LOCALAPPDATA%\FlintEye`
* macOS：`~/Library/Application Support/FlintEye`
* Linuxデスクトップ：`${XDG_DATA_HOME:-~/.local/share}/flinteye`
* systemd：`/var/lib/flinteye`
* Docker：`/data`

アプリケーションのアンインストールでは、デフォルトでデータが保持されます。
Windowsのアンインストーラーには、デフォルトの「いいえ」でデフォルトのユーザーデータフォルダを消去することを確認する別のオプションが用意されています。
他のプラットフォームで明示的にデータを消去するには、FlintEyeを停止し、
ログイン自動起動のエントリを削除して、選択したデータ/録画フォルダを削除してください。
永続化されたデータを削除すべき場合を除き、`docker compose down -v` を絶対に使用しないでください。

<a id="administrator-deployments"></a>
## 管理者デプロイメント

<a id="docker-linux-x86-64--arm64"></a>
### Docker (Linux x86-64 / ARM64)

クローンせずに公開済みイメージを使用するには、[Dockerガイド](DOCKER.ja.md)に従ってください。
以下のコマンドは、プライベートな開発用チェックアウトをビルドします。

```sh
docker compose -f deploy/compose.dev.yaml up -d --build
docker compose -f deploy/compose.dev.yaml exec flinteye cat /data/setup-token
```

SSHトンネル（`ssh -L 18080:127.0.0.1:18080 <server>`）を使用し、
`http://127.0.0.1:18080` を開いて、1回限りのセットアップトークンを入力し、管理者の
パスワードを選択します。トークンは所有者のみの権限で保存され、セットアップ後に
削除されます。ログには書き込まれません。これは、ヘッドレスなsystemdインストールのための初期アカウントフローでもあります。
Composeファイルは、LANでのONVIF検出とWebRTCのためにLinuxホストネットワークを使用します。
オプションのUSBデバイス/ビデオグループのマッピングは、そのファイルに示されています。
Docker DesktopのUSBサポートは含まれていません。テスト済みのamd64/arm64アーカイブを配布するにはリリースワークフローを使用してください。公開時に再ビルドしないでください。

データボリュームはUID/GID 10001に属します。バインドマウントはそのアイデンティティによって書き込み可能である必要があります。コンテナフォルダのパスはコンテナ内のパスです。追加の録画ディスクはすべて明示的にマウントしてください。
ビルド済みイメージにはMediaMTXバイナリが含まれているため、オーケストレーターがその起動とシャットダウンを管理します。

<a id="systemd"></a>
### systemd

`/opt/flinteye` にネイティブLinuxバンドルをインストールし、`flinteye` システム
ユーザー/グループを作成します。`packaging/flinteye.service` を `/etc/systemd/system/` の下にインストールします。
USBキャプチャにはホストの `video` グループが必要です。別のデバイスグループを使用するホストではこれを適宜調整してください。
その後、以下を実行します：

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now flinteye
sudo cat /var/lib/flinteye/setup-token
```

デスクトップインスタンスとsystemdインスタンスで、実行中のデータディレクトリやポートを共有してはなりません。
サービスはログインなしで起動し、デスクトップアプリケーションはログイン後に起動します。

<a id="building-installers"></a>
## インストーラーのビルド

自動ビルド、ソース/ライセンスアーカイブ、およびGHCR公開については、[リリースガイド](RELEASING.ja.md)を使用してください。

ターゲットOSおよびCPUごとに個別にビルドし、Windows/macOSではPython 3.14.10を、
Node.js 22を使用します。Linux Dockerビルダーは、固定されたPython 3.13.18のソースをコンパイルします。
既存のソースワークフロー（`tools/start_orchestrator_stack.py`）も引き続き利用できます。

[文書化されたビルドツール](RELEASING.ja.md#local-native-build)を指定して `bash packaging/build_vendor.sh` を実行します。
これにより、ターゲットCPU用の `vendor/bin/ffmpeg[.exe]`、`vendor/bin/ffprobe[.exe]`、`vendor/bin/mediamtx[.exe]`、
および通知、対応するソース、ビルド設定が準備されます。
FFmpegは `drawtext` と `libx264` をサポートしている必要があります。
選択したバイナリに必要なランタイムライブラリをすべてバンドルしてください。x86-64のバイナリをARM64パッケージに混入させないでください。
FFmpegとFFprobeには、concatデマルチプレイヤーとHTTP/HTTPS/RTSPのサポートが含まれている必要があります。
カメラのURLは、プロセス引数ではなく、プライベートな単一入力マニフェストを通じて配信されます。
ビルドでは、実際のベンダーバイナリを使用して、認証済みHTTPおよびRTSP取り込み、プロービング、スナップショットをパッケージング前に検証します。
ソースのインストールでも同じプライベート入力パスを使用します。
資格情報やクエリトークンを含むカスタムパブリッシャーURLは拒否されます。バンドルされているループバックのMediaMTXパブリッシャーエンドポイントを使用してください。
ランタイム資格情報とプライベートマニフェストは、Windowsにおけるインストールユーザーのプライベートプロファイル/一時ディレクトリのACLに依存します。
HTTPSのONVIFエンドポイントは信頼できる証明書を提示する必要があります。
プライベートカメラCAを使用する管理者は、`REQUESTS_CA_BUNDLE` を介してそのバンドルを提供できます。

```sh
python -m pip install -c packaging/constraints.txt -r requirements.txt -r packaging/requirements-build.txt
python packaging/build_bundle.py --vendor vendor
```

バンドルは `dist/FlintEye` にあります。macOSではさらにアプリとDMGが生成されます。
スクリプトはベンダーのハッシュを `dist/vendor-sha256.json` に記録します。Windowsの場合は、
Inno Setup 6を `packaging/windows.iss` に対して `/DAppVersion=X.Y.Z /DAppArch=amd64`
（または `arm64`）とともに実行します。Linuxの場合は、nFPMをインストールして以下を実行します：

```sh
VERSION=$(python packaging/release.py version) ARCH=amd64 nfpm package --config packaging/nfpm.yaml --packager deb --target dist/
VERSION=$(python packaging/release.py version) ARCH=amd64 nfpm package --config packaging/nfpm.yaml --packager rpm --target dist/
```

ARMビルドには `ARCH=arm64` を使用してください。新しいglibc要件の導入を避けるため、
RPMはRocky Linux 9上でビルドし、DEBは最小ターゲットに対してビルドしてください。
Linuxデスクトップシステムには、グラフィカルセッションとTk/X11ライブラリが必要です。
完全なツールチェーンのネイティブARM64での可用性を公開前に検証する必要があります。

プレビュー版インストーラーは、設定内で新しく公開されたプレビュー版または安定版リリースを確認します。安定版インストーラーはプレビュー版を無視します。ソースチェックアウトはGitで更新されます。FlintEyeがアップデートを自動的にダウンロードまたはインストールすることは決してありません。また、アップデートの確認によって録画が再起動されることもありません。監視を停止し、
設定/インベントリをバックアップし、置換パッケージをインストールして再起動してください。
ロールバックのために以前のパッケージを保持してください。すべてのデータディレクトリ/ボリュームを保持してください。
既存の設定はアップグレード中も保持されます。
`api.host` が `0.0.0.0` に設定されている古い開発版のインストール環境がある場合は、
それを `127.0.0.1` に変更して再起動してください。
LANアクセスのためには前述のHTTPSプロキシを使用してください。
録画を再開する前に、FlintEyeを停止した状態で古い共有 `.playback_cache` を削除してください。

<a id="release-acceptance-matrix-not-a-claim-of-completed-certification"></a>
## リリース受入マトリックス（完了した認証の主張ではありません）

* Windows 10 22H2およびWindows 11：x86-64、ARM64。
* Ubuntu 24.04 LTSおよびそれ以降のテスト済みLTSリリース：x86-64、ARM64。
* Rocky Linux最新の9.xおよび10.x：x86-64、ARM64。
* macOS 14およびそれ以降のテスト済みリリース：Intel、Apple Silicon。
* Raspberry Pi 4/5：64ビットRaspberry Pi OS。リリース前に正確なOSイメージを検証してください。

各ターゲットについて、Python/Nodeなしでのクリーンインストール、パスワード設定/キャンセル、
USBおよびIP入力、2台目のLANデバイスからのライブビデオ、録画/再生、
非ASCIIのユーザー/フォルダ名、フォルダの変更、ボリュームの取り外し、ディスク制限、ログイン自動起動、
ブラウザを閉じる動作と終了の比較、重複起動、アップグレード/アンインストール時のデータ保持をテストしてください。
すべての外部メディアリスナーが認証されていないアクセスを拒否することを検証してください。
実際のカメラでPiのパフォーマンスをテストしてください。一律のカメラ台数を約束しないでください。

<a id="validation-and-development-status"></a>
## 検証および開発ステータス

**開発中 (UNDER DEVELOPMENT)** このリポジトリは現在のソーススナップショットから開始されています。公開インストーラーとGHCRイメージの準備が進められています。古いプライベート成果物は公開リリースではありません。可用性については、[リリース](https://github.com/noguhiro2002/FlintEye/releases)および[Dockerガイド](DOCKER.ja.md)に従ってください。

自動チェックでは、セットアップ/認証、ストレージ保持、再生境界、ワーカーの読み込み、メディアプロセスのクリーンアップ、インストーラー/リリースの整合性、およびプレビューバージョンの比較をカバーしています。フロントエンドは、すべてのプラットフォーム向けに共有ソースからコンパイルされます。ネイティブビルドジョブは、合成メディアを使用してインストール済みパッケージをテストしますが、実際のカメラの動作やすべての最小OSを保証することはできません。

公開プレビューの配布前に、Windows x64、M1 Mac、Linux x64で[受入チェックリスト](ACCEPTANCE.ja.md)を完了し、対応するソース/ライセンスを確認してください。テストされていないターゲットや[既知のUIの問題](KNOWN_ISSUES.ja.md)を明確にしておいてください。ブラウザを閉じても監視はアクティブなままになります。明示的なアプリケーションの終了によって、所有しているAPIおよびメディアプロセスを停止させる必要があります。
