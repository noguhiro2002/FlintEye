# 監視状態の表示とデスクトップ操作

[English](MONITORING.md) · [ドキュメント](README.ja.md) · [停止とアンインストール](STOP_AND_UNINSTALL.ja.md)

これらのコントロールは、**1.1.3開発ビルド**の新機能です。以前にダウンロードしたインストーラーは、置き換えられるまで元の動作を維持します。このビルドはUNDER DEVELOPMENT（開発中）です。[受け入れチェックリスト](ACCEPTANCE.ja.md)に、引き続き必要なデバイスチェックが記録されています。

<a id="find-the-controls"></a>
## コントロールの場所

- **Windows:** FlintEyeアイコンが通知領域にあります。表示されていない場合は、隠しアイコンの矢印を確認してください。
- **macOS:** FlintEyeアイコンが上部メニューバーにあります。メニューおよび通常のDockの「終了」アクションは、どちらも録画の保存完了を待って終了します。
- **Linuxデスクトップ:** 小さなコントロールウィンドウが常に利用可能です。X11トレイがサポートされている環境では、アイコンをクリックするとコントロールが開きます。デスクトップ拡張機能は自動的にはインストールされません。
- **Docker、systemd、CLI:** トレイ、コントロールウィンドウ、カメラ設定ウィンドウ、ログイン時起動のエントリは作成されません。サーバー運用には `--headless` を明示的に使用してください。デスクトップディスプレイのないLinuxおよびリモートのmacOSシェルセッションでは、画面を表示しない起動が自動的に選択されます。

1コマンドでのデスクトップインストールでは、インストーラーと同じコントロールが使用されます。デスクトップコントロールが表示されるかどうかは、実行環境によって決まります。

<a id="understand-the-indicator"></a>
## インジケーターの見方

目のアイコンには、色付きのバッジと形状があります。メニューやウェブアプリには文字とカメラの数も表示されるため、色だけがインジケーターではありません。

| インジケーター | 意味 |
| --- | --- |
| 緑色、再生シンボル | 設定された監視対象がデータを受信しています。録画は受信とは別にカウントされます。 |
| 赤色、停止シンボル | 監視が意図的に停止されました。Settings とAPIは引き続き利用可能です。 |
| 赤色、十字 | メディアサーバーまたは監視対象のすべてのカメラ映像を利用できません。 |
| アンバー（橙）、警告シンボル | 起動中、停止中、録画の保存処理中、一部カメラの障害、または状態を取得できないことを示します。 |
| 灰色、ダッシュ | 初期設定が完了していないか、監視対象のカメラが選択されていません。 |

カウントは、**設定済みカメラ**、**監視対象**、**受信中カメラ**、**録画中カメラ**を区別します。実行中のプロセスや有効化された録画チェックボックスのみでは、受信や録画の証明にはなりません。ヘルスチェックは約2秒ごとに実行され、受信が進まない状態が15秒続くと、フィードが停止（ストール）したとみなされます。カメラの詳細には、最後に観測された受信時刻が含まれます。短い再起動により、一時的にアンバーが表示されることがあります。

FlintEyeは、同梱するMediaMTXの状態確認APIを、このコンピュータ内からのみ接続できる設定で有効にします。外部のMediaMTXサーバーは、APIを公開するように再設定されません。状態を取得できない場合は「Status unavailable」と表示します。

<a id="stop-monitoring-or-quit"></a>
## Stop monitoring または終了

**Stop monitoring** は、カメラ映像を送信する処理を停止し、録画の完了とインデックス登録を待ってから、管理対象のメディアサーバーを停止します。ウェブアプリ、設定、およびネイティブコントロールは開いたままになります。再開するには **Start monitoring** を使用します。**Restart monitoring** は、監視が有効な間のみ利用可能です。処理中の操作がある場合、コントロールの連続クリックは無効になります。

**Quit FlintEye** は録画を終了し、APIとネイティブコントロールも閉じます。ブラウザを閉じたりサインアウトしたりしても、監視は実行されたままになります。このFlintEyeが起動したプロセスだけを終了します。無関係なブラウザ、FFmpegインスタンス、外部メディアサーバーはそのまま保持されます。

完了チェックは**最大30秒**待ちます。ストレージが利用できない、完了コールバックが欠落している、またはインデックスエラーが発生している場合、橙色の「Finishing recordings」と、保存が終わっていない録画ファイルの数を表示します。ストレージを再接続し、**Retry Stop（停止を再試行）**を使用してください。別の **Force quit（強制終了）** アクションには確認が必要であり、不完全な録画が残る可能性があります。ファイルシステムやオペレーティングシステムのシャットダウン遅延により、総終了時間が完了待機期間を超える場合があります。

通常のアプリケーション終了とWindowsのアンインストーラーは、同じ完了チェックを使用します。OSの終了/アンインストールには制限付きフォールバックがあるため、非表示のアプリケーションが無期限に実行され続けることはありません。ローカルの `last-monitoring-stop.json` 確認記録は、完了した録画の停止と、強制または未検証の停止を区別します。Windowsの `last-stop-result.json` はプロセスのクリーンアップを個別に報告します。実機での確認時に最後のセグメントを再生してください。プロセスの終了だけでは、使用可能なメディアの証明にはなりません。FlintEyeへの録画完了通知を備えず、別のサービスが管理している録画は、このチェックでは保存完了を確認できません。その録画サービス側で停止・確認してください。

個別の `recording-events.sqlite3` 台帳は、セグメントの作成/完了を追跡します。既存の `recordings.sqlite3` にある録画一覧と保存期間・容量のルールは維持します。未完了のファイルは自動整理の対象にしません。前回起動時に完了を確認できなかったファイルは、その数を警告として表示します。

<a id="startup-preferences"></a>
## 起動時の設定

**Settings → Basic → Runtime & access → Monitoring and startup** を開きます。これらの設定は即座に保存されます。

- **Always resume monitoring when FlintEye starts:** デフォルトではオフです。オフの場合、明示的な停止はアプリとコンピュータの再起動をまたいで停止状態を維持します。実行中に終了すると実行中の設定が維持されるため、再オープン時に監視が再開されます。以前の停止後も監視を開始するには、このオプションをオンにします。
- **Start FlintEye when I log in:** 現在のユーザー向けにデスクトップアプリケーションを起動します。これは監視設定とは独立しています。この設定は、ローカルのデスクトップインストールを使用している管理者のみが利用可能です。別のプロファイルやインストールに属する登録は保持されます。

監視を停止すると、録画の保存処理が終わった後にデスクトップの自動スリープ防止が解除されます。手動でのスリープ、ログアウト、OSのシャットダウンは、引き続き監視を中断させます。サーバーはログイン中のデスクトップに依存するのではなく、Docker/systemdを使用する必要があります。

<a id="network-access"></a>
## ネットワークアクセス

デスクトップのウェブアプリはデフォルトでループバックでリッスンします。Windowsのファイアウォールのプロンプトは、MediaMTXのWebRTCメディアトランスポートに関連している可能性がありますが、それ自体がウェブアプリがLANに公開されていることを意味するわけではありません。プロンプトを消すためだけに、より広いネットワークアクセスを許可しないでください。ローカル視聴とLAN視聴は別々のチェックです。他のデバイスについては、[HTTPS/LANデプロイガイド](DISTRIBUTION.ja.md#user-installation)に従い、必要なネットワークとポートのみを許可してください。保護されたルートには引き続き認証が必要です。

<a id="api-and-build-identity"></a>
## APIとビルドID

`GET /api/v1/status/monitoring` にはビューアーアクセスが必要であり、デスクトップコントロールと同じ状態を報告します。既存の管理者専用の `POST /api/v1/control/start`、`stop`、`restart` ルートは共有コントローラーを使用します。`GET /api/v1/health` はAPIが応答していることを示しますが、カメラの受信を証明するものではありません。

**Information** にバージョン、開発チャネル、ビルド元のコミットが表示されます。ビルド情報のないソース版では、コミットが記録されていないと表示します。録画一覧の **Date basis → Recording time** は、保存完了時に登録した撮影時刻を使います。**File update time** はファイルの更新時刻を使い、**Updated** と表示します。撮影時刻がないファイルは **Recording time unavailable** と表示します。
