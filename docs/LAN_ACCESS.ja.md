# LANアクセスと証明書の信頼 — 1.2.0 開発版

[English](LAN_ACCESS.md) · [インストール](INSTALL.ja.md) · [監視](MONITORING.ja.md)

**UNDER DEVELOPMENT。これらの変更には1.2.0パッケージの再ビルドが必要です。公開されている1.1.3-preview.1には含まれていません。物理LANおよびモバイルでの承認は保留中です。**

## アクセスの有効化

サーバーコンピューター上で、FlintEyeに表示されたセットアップトークンを使用して、ブラウザーでの管理者セットアップを完了します。**Settings → Runtime & access → LAN connection and certificate trust**を開きます。**Enable LAN HTTPS**を選択し、このサーバーに実際に割り当てられているIPv4アドレスと、接続を許可するプライベートソースネットワーク（例: `192.168.1.0/24`）を入力します。このPCのみで使用する場合は、アクセスを無効のままにしてください。

接続設定を保存します。**Save public certificate and connection guide**を選択します。表示されたフォルダーには、CA証明書、そのフィンガープリント、iOS/iPadOS証明書プロファイル、およびこれらの手順書が含まれています。秘密鍵やセットアップトークンは含まれていません。USBストレージ、AirDrop、または既存の認証済みファイル共有など、管理下にある方法でこのフォルダーを転送してください。CAのSHA-256フィンガープリントを信頼する前に、サーバーの表示と比較してください。ブラウザーの証明書警告を回避して証明書を取得しないでください。

Windowsでは、**allow selected LAN access**を実行するとUACの承認と、実際のネットワーク設定の二段階の確認が求められます。ヘルパーは、設定されたAPIポート（デフォルトは18080）およびWebRTC UDP 8189に対して、選択したサーバーIPと許可されたソース向けに、**プライベート**ネットワーク限定でHTTPS TCPを追加します。承認を拒否した場合は、ローカル操作のみが維持されます。ドメインネットワークでは、管理者管理のルールが必要です。LinuxおよびmacOSでは、アクティブなファイアウォールでこれらの特定のインバウンドフローを許可するようマシン管理者に依頼してください。FlintEyeはファイアウォールを無効化しません。macOSでは、アプリケーションレベルのネットワーク権限を求められる場合があります。MediaMTX TCP 8554、8889、9997、または未使用のRTPポートを公開しないでください。

FlintEyeを再起動します。許可された別のデバイスで **`https://SERVER-IP:18080`** を開きます（異なるAPIポートを選択した場合はそれを使用してください）。ログイン、ロールによって許可された設定、ライブビュー、マルチビュー、録画再生には同じアドレスを使用してください。ローカルサーバーの制御アドレスは復旧用に `http://127.0.0.1:18080` のまま維持されます。LAN IPでのプレーンなHTTPはエントリーポイントではありません。

サーバーには選択したアドレスを維持させる必要があります。ルーターのDHCP予約または管理者割り当てアドレスを使用してください。スリープ状態では録画や閲覧ができないため、サーバーをスリープさせないでください。ポートフォワーディング、パブリックインターネットアクセス、ルーターの自動設定、TURNリレーは提供されていません。

## 各閲覧デバイスで証明書を一度だけ信頼する

インストール固有のCAを使用して、サーバー証明書の信頼を確立できます。フィンガープリントを確認した後にのみ、また信頼を追加する権限があるデバイスでのみインストールしてください。デバイス管理者や組織のポリシーにより、この操作が禁止されている場合があります。FlintEyeはサイレントに信頼をインストールすることや、CA秘密鍵をエクスポートすることはありません。

- **Windows Edge/Chrome:** `FlintEye-CA.crt` を開き、現在のユーザー用の「証明書のインストール」を選択し、明示的に **信頼されたルート証明機関** を選択します。表示されたフィンガープリントを確認します。必要に応じてブラウザーを再起動します。この特定のCAは、後で現在のユーザーの証明書マネージャー (`certmgr.msc`) から削除してください。他の証明書は削除しないでください。
- **macOS Safari/Chrome:** `FlintEye-CA.crt` をキーチェーンアクセスを使用してログインキーチェーンにインポートします。フィンガープリントを確認し、信頼設定を開いて明示的にSSL信頼を許可します。macOSでアカウントのパスワードを求められる場合があります。信頼を取り消すには、キーチェーンからこのFlintEye証明書を正確に削除してください。[Apple 証明書の信頼](https://support.apple.com/guide/keychain-access/change-the-trust-settings-of-a-certificate-kyca11871/mac)
- **Linux:** CAをブラウザーの認証局証明書ストアにインポートするか、管理者に依頼して、そのブラウザーが使用するOSの信頼ストアに追加してもらいます。Firefoxは独自の証明書ストアを使用する場合があります。フィンガープリントを検証し、終了時にはこのインストールの認証局のみを削除してください。
- **iPhone/iPad Safari:** `FlintEye.mobileconfig` を開き、設定 → 一般 → VPNとデバイス管理 でダウンロードしたプロファイルをインストールした後、設定 → 一般 → 情報 → 証明書信頼設定 でこのFlintEyeルートを有効にします。プロファイルをインストールするだけではTLS信頼は有効になりません。信頼を取り消すには、正確にFlintEyeプロファイルを削除してください。[Apple の手順](https://support.apple.com/en-ie/102390)
- **Android Chrome:** `FlintEye-CA.crt` をデバイスにコピーし、セキュリティ → 暗号化と認証情報（名称はメーカーにより異なります）の下にある **CA証明書** インストールオプションを選択します。デバイスのロック解除や管理者の承認が必要になる場合があります。このインストールのフィンガープリントを検証してください。終了時にはユーザー認証情報の下からこの証明書を正確に削除してください。すべての認証情報をクリアしないでください。管理されたデバイスやブラウザーでは、ユーザー認証局が拒否される場合があります。[Google 証明書のヘルプ](https://support.google.com/pixelphone/answer/2844832)

## 初回所有権と日常的な使用

LANからの訪問者は、サーバーの使い捨てセットアップトークンなしに管理者アクセスを要求することはできません。セットアップ前に有効化されたヘッドレスインストールの場合は、所有者がデータディレクトリ内の `setup-token` を読み取り、信頼されたHTTPS接続経由で入力します。トークンは30分で期限切れになります。サーバーを再起動するか、サーバー上の **Address and setup assistance → Renew setup token** を使用して置き換えてください。セットアップの試行回数は制限されています。トークンやパスワードは、URL、共有手順書、ログ、スクリーンショットに決して表示しないでください。

セットアップ後、既存の管理者アカウントはアプリやOSの再起動、再インストール後も維持されます。閲覧者のアクセスを共有する前に、閲覧者用パスワードを設定してください。閲覧者は承認された動画や録画を視聴できますが、管理設定の変更や監視の開始/停止はできません。ブラウザーを閉じてもサーバーは稼働し続けます。監視を一時停止するには **Dashboard → Stop monitoring** を使用し、録画を終了してすべてのバンドルプロセスを停止するにはネイティブの **Quit FlintEye** アクションを使用してください。

## 証明書の更新と復旧

サーバー証明書の有効期限は90日で、期限の30日前から同じインストールCAを使用して更新されます。新しいTLS接続では更新された証明書が使用されますが、クライアント側で新しいCAは不要です。CAの有効期限は5年です。有効期限はローカルの接続設定に表示されます。期限切れ前に明示的に更新し、すべてのデバイスにガイドを再配布してください。**Renew trust certificate** はCAを置き換えるため、すべての閲覧デバイスで信頼の再設定が必要です。プライベートデータディレクトリを安全に保管してください。そのTLS秘密鍵をサポートのために送信してはなりません。

**Renew trust certificate**を選択した後、新しい証明書でHTTPSリスナーが動作するようにFlintEyeを再起動してください。その後、各デバイスで信頼設定を更新してから再接続してください。

DHCPによってサーバーIPが変更された場合、FlintEyeは別のインターフェースを自動的に公開することはありません。ローカルサーバーアドレスを開き、新しいIPを選択して更新されたガイドをエクスポートし、再起動してください。同じCAの下で新しいリーフ証明書が発行されます。ローカルポートが使用中の場合は、競合しているインスタンスを停止するか、ランチャーの `--port` 上書きオプションを使用してください。コントロールウィンドウに実際のローカルURLが表示されます。

到達不能なページ、信頼されていない証明書、拒否されたソースネットワーク、誤った資格情報、ビデオが表示されないページは、それぞれ異なる問題です。まずローカル設定エラー、選択したバインド用アドレス、ファイアウォール、証明書のフィンガープリントを確認してください。ビデオについては、WebRTCとUDP 8189によってアドバタイズされた選択済みIPを確認してください。HTTPSページにアクセスできることだけでは、ビデオへの到達性は証明されません。ブラウザーがローカルネットワークアクセスを要求する場合もあります。サイトごとに意図的な判断を行ってください。パブリックネットワークプロファイルは自動的には開かれません。

HTTPSリスナーを閉じるには、LANアクセスを無効にして再起動してください。Windowsでは、専用ボタンを使用してこのインストールのファイアウォールルールを削除してください。不要になったら、各閲覧デバイスからFlintEye CAを削除してください。アンインストールしてもクライアント側の信頼は自動的には削除されません。保持されたデータには、既存のインストールの証明書が含まれています。明示的なデータ削除を行うとそれらの証明書も削除されるため、データを消去して再インストールした場合は、改めて信頼の設定が必要です。

## ヘッドレスおよび既存のプロキシ環境

明示的なヘッドレス環境のオプトインとして、サービスが使用するのと同じデータディレクトリを指定して、インストールされた実行ファイルを通常のサービスユーザーとして実行します。

```sh
/opt/flinteye/FlintEye --headless --data-dir /PATH/TO/DATA --lan-address 192.168.1.10 --lan-source 192.168.1.0/24
```

そのプロファイルを使用している既存のインスタンスをすべて先に終了してください。インスタンス停止後にガイドをエクスポートするには、以下を使用します。

```sh
/opt/flinteye/FlintEye --data-dir /PATH/TO/DATA --export-connection-guide
```

ローカルのみの操作に戻すには、その同じプロファイルで `--disable-lan` を使用してください。これらのフラグはLinuxファイアウォールを管理しません。管理者管理の既存のリバースプロキシは、組み込みのLANモードを無効にした状態で引き続き使用できます。パブリックWeb URL、APIバインド、およびメディアアップストリームは個別の設定です。組み込みのLANパスは、転送されたアイデンティティヘッダーを信頼しません。

Docker Desktopで提供されるブリッジComposeは、ホストブラウザー専用です。LAN Dockerサーバーの場合は、ホストネットワーク設定と上記の明示的なLAN設定を使用してLinux Engineを使用してください。[Docker ](DOCKER.ja.md)
