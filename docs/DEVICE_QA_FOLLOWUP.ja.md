# 2026-11-15 デバイスレビューのフォローアップ

[English](DEVICE_QA_FOLLOWUP.md) · [受入チェックリスト](ACCEPTANCE.ja.md)

提供されたレビューでは、コミット `fc95bea3732f84c38e1c7a5d8a806e9fb0824548` (アプリケーション 1.1.2) がテストされました。`778a334` で共有された WebApp の修正はその後に適用されたものです。そのアップデートも、このフォローアップも、以前の Actions 実行からすでにダウンロードされたインストーラーを変更するものではありません。受入チェックを繰り返す前に、このソースからリビルドしてください。

レビューにより、1台の Windows x64 マシンでの短い USB キャプチャ、録画、UI 再生、および Mac ARM64 と Linux のソースインストールにおける合成の録画・ダウンロードが確認されました。すべてのプラットフォーム、長時間録画、IP カメラ、またはすべてのインストール経路が検証されたわけではありません。それらの結果は、あくまでその正確な以前のビルドに対する有用な証拠であり、置換ビルドに対する一括合格を意味するものではありません。

<a id="findings-and-changes"></a>
## 検出事項と変更点

| 検出事項 | 変更点および残りの検証 |
| --- | --- |
| `copying...dSYM` テストバイナリで Mac の署名が失敗する | ランタイムライセンスコレクターがテキスト通知を選択し、オブジェクトコード／デバッグバンドルを除外するようになりました。リビルドによって生成されたランタイム通知と古い DMG ステージングがクリアされますが、ベンダーのソース／ライセンスは保持されます。最終的な DMG とインストール済みコピーの署名チェックは必須であり、改変されたコピーは必ず失敗しなければなりません。Mac での隔離を考慮した初回起動を再度実行してください。 |
| Gatekeeper の拒否 | 現在のプレビューポリシーは、Developer ID や公証なしのアドホック署名のままです。整合性と信頼性は、署名レポート内の個別の結果です。Gatekeeper の拒否は、信頼チェックの成功ではありません。自動化された信頼できる配布には、個別の Developer ID 署名／公証の設定と承認が必要です。OS の保護機能が無効化されることはありません。 |
| シェルのワンライナーコマンドがダウンロード失敗時に成功を返す | README のコマンドは一時ファイルにダウンロードし、ダウンロードが成功した場合にのみ実行します。ダウンロードおよびスクリプトの終了ステータスが伝播され、一時ファイルはクリーンアップされます。合成成功、HTTP 失敗、接続失敗、不完全な転送、スクリプト失敗がテストされます。実際の公開リリースダウンロードはまだ利用できません。 |
| API ポートが Settings と異なる | **API listening now** は実行中のサーバーのアドレスを使用します。編集可能なホスト／ポートフィールドは、次回の起動時の値として明示的に保存されます。CLI のオーバーライドは一時的なままであり、`--port` がない場合、ランチャーは保存されたポートを優先します。実行中のインスタンスを再度開く場合、保留中の保存ポートの変更後であっても、実際のリスナーを使用します。 |
| ゴミ箱に入れた後も Mac の LaunchAgent が残る | トレイアクション **Disable start at login and quit** と CLI `--disable-autostart` は、登録を削除しつつデータを保持します。新規登録では、特定のアプリのコピーとプロファイルが指定されます。自動セットアップは、他のインストールの登録を上書きしません。手動でのゴミ箱への移動だけではクリーンアップを呼び出すことができません。[停止とアンインストール](STOP_AND_UNINSTALL.ja.md)に従い、次回のログインを確認してください。 |
| Windows の停止結果が不明瞭である | ヘルパーは明示的なプロファイルパスを検出し、`-DataDir` をサポートし、現在のプロセスのアイデンティティを検証し、`last-stop-result.json` を書き込みます。通常の要求、タイムアウト、強制終了、不完全な停止が区別されます。プロファイルの検出には、実行中のインスタンスの解決済みデータディレクトリが使用されます。スコープ付き停止では、ランチャーが終了した場合や停止中に子プロセスが開始された場合でも、所有している子孫が追跡されます。アンインストールでは、自身のインストールに対する制限付きフォールバックが引き続き許可されます。親プロセスの停止完了は、メディアの正常終了（graceful shutdown）の証明ではありません。停止時にアクティブだった録画を検証してください。 |
| 設定適用時のカメラ終了 `4294967264` | この値は `-32` を表しており、提供されたログによってその正確な原因が特定されているわけではありません。計画されたメディア変更では、MediaMTX の再設定・再起動の前にパブリッシャーが停止されるようになり、停止時にはレコーダーよりも前にパブリッシャーが順序付けられます。メディア構成を変更しない Settings の変更では、ストリームが実行されたままになります。スタック全体の再起動では、パブリッシャーが 1 回起動します。予期しない非ゼロ終了は引き続きエラーとなります。元の USB シナリオを再確認し、再発した場合は子ログを保持してください。 |
| 古い製品名 | ブラウザーのタイトル、残りのヘルプテキスト、およびデフォルトのラベルには **FlintEye** が使用されています。正確な履歴上のデフォルトラベルは、設定の読み込み時に正規化されます。カスタムタイトル、内部識別子、パス、および API ルートは維持されます。 |
| Settings が一時的にデフォルトを表示する | `778a334` で既に対応済みです：設定が読み込まれるまで、読み込み中／利用不可の状態が表示されます。 |
| Windows パッケージにパブリッシャーの署名がない | 引き続き意図されたプレビューポリシーであり、[インストール](INSTALL.ja.md)に文書化されています。この変更の一環として、証明書の購入や署名アイデンティティの設定は行われていません。 |
| 古いチュートリアル動画 | GIF/MP4 は現在の 5 ステップガイドを表示するようになり、ソースのバージョン／日付とスコープが README に記載されています。これは合成応答とゼロ台のカメラによる UI ツアーであり、インストール／録画／アンインストールのデモではありません。元の WebM は保持されます。 |
| Linux の venv/ensurepip パッケージがない | [ソースセットアップ](MANUAL_INSTALL.ja.md)で、ディストリビューションのバージョンに一致する venv と Tk の前提条件について説明されるようになりました。 |

## 追加のローカル USB チェック

所有者の要件に基づき、接続された 2 台の USB カメラを、隔離されたプロファイルを使用して Linux 開発ホスト上でテストしました。README のメイン動画には、Live View、2 台のカメラ間の切り替え、正常な 2 入力 Multiview、および実際の録画再生が表示されています。カメラのストリームは 640×480 であり、Multiview は 1280×480 です。そのメインキャプチャセッションからの 48 個の記録されたファイルすべてが FFprobe を通過し、48 個の録画インデックスエントリと一致しました。別の開発者用動画では、Swagger で `GET /api/v1/viewer/cameras` を実行し（HTTP 200）、返された `addresses.webrtc_url` を開いて、実際の 640×480 WebRTC 再生を行っています。

通常の停止要求により、インスタンス制御ファイルが削除され、API/MediaMTX リスナーが閉じられ、両方のカメラが解放されました。以前の単一カメラチェックでも、9 個の記録されたファイルすべてとそのインデックスエントリが検証されました。デモキャプチャでは、15 fps、1 秒のカメラキーフレーム間隔、8 秒のサムネイルタイムアウトを使用しています。これらの短い Linux ソーステストは、Windows メディアの正常終了、長期的な信頼性、またはネイティブパッケージの受け入れを確立するものではありません。初回実行ガイドは、引き続き別の合成 UI ツアーとなります。

<a id="recheck-on-the-new-artifacts"></a>
## 新しい成果物での再確認

- 成果物全体で同じソースコミットを確認してください。macOS の `-signature.json` レポートをチェックし、Gatekeeper を無効化せずに、隔離されたダウンロードからの初回起動を繰り返します。
- `--port 18765` から開始し、実際のリスナーと **API listening now** を比較し、そのオーバーライドなしで再起動して保存されたポートを確認します。
- Windows では、デフォルトおよびカスタムの両方のデータディレクトリをテストし、`last-stop-result.json` を検査し、録画がアクティブな状態で終了／アンインストールをテストします。FFprobe でファイル、その UI 再生、および録画インデックスエントリを確認し、関係のないプロセスが実行され続けていることを検証します。
- Mac では、削除準備メニュー、保持された録画／設定、および次回のログインをテストします。通常の Dock の「終了」を「強制終了」とは別にテストします。
- 対象のディストリビューションおよびデスクトップで、Linux の DEB/RPM インストール／削除を繰り返します。コンテナベースのパッケージチェックは、ネイティブデスクトップの受け入れを確立するものではありません。
- カメラ、スリープ／復帰、長期稼働、クォータ、およびアップグレードのチェックを [受入](ACCEPTANCE.ja.md) で継続してください。この作業は、リリースの公開やこれらすべてのシナリオの保証を行うものではありません。
