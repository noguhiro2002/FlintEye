# 既知の問題と WebApp のレビュー状況

[English](KNOWN_ISSUES.md) · [Documentation](README.ja.md)

現在の公開版は [Preview 10](https://github.com/noguhiro2002/FlintEye/releases/tag/v1.2.0-preview.10) です。2026-11-15 のブラウザーレビューで見つかった下表の26グループは、このプレビューに修正を含めています。検証結果と残る確認項目は[現在の実機チェックリスト](RELEASE_CHECKLIST_1_2_0.ja.md)で確認できます。

<a id="changes-from-the-review"></a>
## レビューからの変更点

| レビューの指摘事項 | 更新されたソースコードでの動作 |
| --- | --- |
| 1, 2, 13, 25 — Settings の下書きと読み込み | ナビゲーション、更新、および両方の破棄アクションでは、保存されていないフォームや JSON の編集内容を破棄する前に確認が行われます。デバイス/アカウントの個別操作では、既存の変更を保存するか破棄する必要があります。高度な JSON にはアクセス可能なラベルと独自の変更状態があり、それを置き換える際には保存されていないフォームの変更について警告が表示されます。ステータスが不完全なカウントで変更を過小評価しなくなりました。USB の検出に失敗しても、他の設定は引き続き利用可能です。設定の欠落は、デフォルトのステータス主張が設定されるのではなく、利用不可として表示されます。 |
| 19, 21, 22, 23, 24 — カメラの同一性とインスペクション | カメラを切り替えると PTZ 状態が分離されます。削除または編集された下書きは、古くなったインスペクション応答を拒否します。新しいカメラのパスは一意であり、重複または空のパスは保存前に拒否されます。インスペクションの失敗によって以前の成功がクリアされます。インスペクションでは、設定を自動的に変更するのではなく、明示的な **Apply recommended FPS** アクションが提示されます。 |
| 3 — 認証 | 利用できない認証エンドポイントは、パブリックアクセスを主張するのではなく、エラーと**接続の再試行**を表示します。ネイティブのフォルダーピッカーを除き、リクエストには制限された待機時間があり、ネイティブのフォルダーピッカーはユーザーの入力を待ちます。 |
| 16, 18 — 録画プレイヤー | プレイヤーを開くとフォーカスが内部に移動し、キーボードナビゲーションが内部に維持され、背景のコントロールが無効になり、閉じるときにフォーカスが復元されます。再生コントロールはその録画を識別します。 |
| 17, 20 — 録画クエリ | 日付範囲が逆になっている場合は、無効なクエリを送信せずにインラインエラーが表示されます。Recordings とストリームフィルターは独立して読み込まれ、フィルターリクエストが失敗しても利用可能なフッテージは非表示になりません。保持された結果は、フィルターの変更中または更新の失敗時に、以前の結果として識別されます。 |
| 6, 7, 26 — Live View および Multiview | ポーリングは順番に実行され、古くなった応答は無視されます。削除された選択肢は、利用可能なソースにフォールバックします。読み込み中、サービスの失敗、および完全に空の設定には、それぞれ明確なメッセージが表示されます。 |
| 4, 5 — 小型画面 | ヘッダー、コントロール、カメラカード、テーブルは、幅が狭い場合に折り返されるか縮小します。長い名前や URL によってページが強制的に広げられることはなくなりました。モバイルナビゲーションは、そのコンテンツに必要な高さのみを使用します。 |
| 8 — Settings の検索 | エンコーダーが含まれています。検索では、すべてのフィールドを約束するのではなく、そのスコープが設定カテゴリと一般的なキーワードであることが説明されます。 |
| 9, 10 — セットアップとサインイン | セットアップフィールドでは、間隔を空けた垂直レイアウト、FlintEye のブランディング、および表示されるパスワード要件が使用されます。必須のサインインでは、移動先のない「戻る」アクションが表示されません。 |
| 11, 12 — アクセシブルな状態とコントラスト | ナビゲーションはその現在のページを公開し、カメラと Multiview のセレクターはその選択状態を公開します。カメラコントロールは選択ボタンから分離されています。小さな PTZ の説明テキストは、より強いコントラストを持っています。 |
| 14, 15 — ガイダンスと空の状態 | ガイドを開いても、あたかもアクティブであるかのように別のページが装飾されることはなくなります。カメラ、出力、録画の空の状態では状況が説明され、空の録画リストではページネーションが省略されます。 |

<a id="validation-and-remaining-limits"></a>
## 検証と残りの制限事項

Preview 10 はビルド時の36件中28件、公開経路の14件中12件が全7段階に合格しました。残る macOS のビルド時8件・公開経路2件は、インストール・整合性確認・削除に合格し、導入後のアプリの動作は初回起動の承認待ちです。[ビルド結果](https://github.com/noguhiro2002/FlintEye/actions/runs/45609459603) · [公開経路の結果](https://github.com/noguhiro2002/FlintEye/actions/runs/45624057667)

当初問題が出た Windows PC、macOS の利用許可、別端末からの LAN 接続、連続運転などの実機確認は未完了です。アドホック署名によるファイルの整合性確認と、macOS の起動承認は別に記録します。

回帰テストスイートでは、ビルド済みフロントエンド、Chromium、および合成 API 応答を使用しています。遅延および失敗したリクエスト、下書きの保護、カメラの切り替え、キーボード操作、および狭いレイアウトをテストします。外部ホストへのリクエストをブロックし、物理カメラには接続しません。テストコマンドについては、[貢献](../.github/CONTRIBUTING.ja.md)を参照してください。

- **実機での受け入れが引き続き必要です:** Windows および macOS のデスクトップ動作、物理 USB/IP カメラ、PTZ の移動/停止、マイク/プライバシーの権限、スリープ/復帰、最小 OS のサポート、および実際の動画デコードは、対象のマシンで確認する必要があります。Linux ブラウザのテストでは、すべてのブラウザまたはスクリーンリーダーとの互換性は確立されません。
- **競合する設定は自動的に統合されません:** 競合が発生した後も、下書きは画面に残ります。下書きを明示的に破棄して最新の設定を再読み込みする前に、必要な変更をコピーしてください。
- **デプロイガイダンスが異なります:** ブラウザを閉じても監視は実行続行されます。デスクトップユーザーは **Stop monitoring** でカメラを一時停止するか、**Quit FlintEye** でアプリケーションを終了します。Docker/systemd ユーザーはサーバーサービスを停止します。
- **リリース状況:** 公開開発プレビューには、完全なビルドの成功と対応するソース/ライセンスのレビューが必要であり、未完了のmacOS初回起動チェックおよび実機確認については開示されています。安定版への昇格には[実機での受け入れ確認チェックリスト](ACCEPTANCE.ja.md)も必要です。CIの成功は、それらのデバイスチェックを完了させるものではありません。

- **API access の案内:** イベント用トークンの場所を旧 Recording 設定として案内する文字列が残っています。現在は **Settings → Advanced → Integrations & API → Event recordings** を使ってください。アプリ内の文言は今後の更新で修正する対象です。

再現可能な新しい問題は、[Issues](https://github.com/noguhiro2002/FlintEye/issues) から報告してください。レポートから資格情報、セットアップトークン、プライベートカメラの URL、個人のフッテージを削除してください。脆弱性については、[プライベートセキュリティチャネル](../.github/SECURITY.ja.md)を使用してください。

<a id="monitoring-controls-in-113"></a>
## 監視コントロール

トレイと WebApp は監視状態を共有しています。[監視コントロール](MONITORING.ja.md)と[受け入れチェックリスト](ACCEPTANCE.ja.md)を参照してください。ネイティブメニューのクリック、スリープ/復帰、物理 USB の再接続、および 24 時間の操作は、対象のコンピューターごとに個別に記録する必要があります。自動化されたプロセステストでは、それらの動作は保証されません。タイムライン、一括エクスポート、完全な日本語 UI は未提供です。管理者は **Information → Save diagnostics** から診断情報を保存できます。

[1.2.0 のフォローアップ](DEVELOPMENT_1_2_0.ja.md)には、元の指摘と残る実機確認を記録しています。Preview 10 は LAN HTTPS、診断情報の保存、カメラ音声に対応しています。診断情報には生のログ・設定、カメラ URL、映像、認証情報を含めません。Web UI は英語です。Developer ID による署名・公証、録画タイムライン、一括エクスポートは未提供です。
