# 既知の問題と WebApp のレビュー状況

[English](KNOWN_ISSUES.md) · [Documentation](README.ja.md)

FlintEye は**UNDER DEVELOPMENT**であり、安定版ではありません。2026-11-15 の Terra ブラウザのレビューにより、26 グループのインターフェースの欠陥が特定されました。以下の変更は、現在のソースコードにおけるそれらのグループに対処するものです。これらの変更前にビルドされたインストーラーアーティファクトには依然として以前のインターフェースが含まれているため、Windows または macOS でテストする前に、更新されたソースから再ビルドしてください。

<a id="changes-from-the-review"></a>
## レビューからの変更点

| レビューの指摘事項 | 更新されたソースにおける挙動 |
| --- | --- |
| 1, 2, 13, 25 — 設定の下書きと読み込み | ナビゲーション、「更新 (Refresh)」、および両方の「破棄 (Discard)」アクションでは、保存されていないフォームや JSON の編集内容を破棄する前に確認が行われます。個別のデバイス/アカウント操作を実行するには、既存の変更を保存または破棄する必要があります。高度な JSON にはアクセシブルなラベルと独自のダーティ状態があり、それを置き換える際には保存されていないフォームの変更について警告が表示されます。ステータスが不完全なカウントで変更内容を過小評価することがなくなりました。USB の検出に失敗しても、他の設定は引き続き利用可能です。設定の欠落は、デフォルトのステータス主張が入力されるのではなく、利用不可として表示されます。 |
| 19, 21, 22, 23, 24 — カメラの識別とインスペクション | カメラを切り替えると PTZ 状態が分離されます。削除または編集された下書きは、古いインスペクション応答を拒否します。新しいカメラパスは一意であり、重複または空のパスは保存前に拒否されます。インスペクションの失敗により、前回の成功状態がクリアされます。インスペクションでは、設定を自動的に変更する代わりに、明示的な **Apply recommended FPS** アクションが提示されます。 |
| 3 — 認証 | 利用できない認証エンドポイントは、公開アクセスを主張するのではなく、エラーと **Retry connection** を表示します。リクエストには制限された待機時間が設定されますが、ユーザーの入力を待つネイティブのフォルダーピッカーは例外となります。 |
| 16, 18 — 録画プレーヤー | プレーヤーを開くと内部にフォーカスが移動し、キーボードナビゲーションが内部に維持され、背景のコントロールが無効化され、閉じるときにフォーカスが復元されます。再生コントロールはその録画を識別します。 |
| 17, 20 — 録画のクエリ | 無効なクエリを送信することなく、逆転した日付範囲にインラインエラーが表示されます。録画とストリームのフィルターは個別に読み込まれ、フィルターリクエストが失敗しても利用可能な映像が隠されることはありません。フィルターの変更中または更新の失敗時に、保持された結果が以前の結果として識別されます。 |
| 6, 7, 26 — ライブビューとマルチビュー | ポーリングは順次実行され、古くなった応答は無視されます。削除された選択項目は、利用可能なソースにフォールバックします。読み込み中、サービスの障害、および完全に空の設定には、それぞれ明確なメッセージが表示されます。 |
| 4, 5 — 小型画面 | ヘッダー、コントロール、カメラカード、およびテーブルは、狭い幅で折り返されるか縮小します。長い名前や URL によってページが強制的に広げられることはなくなりました。モバイルナビゲーションは、そのコンテンツに必要な高さのみを使用します。 |
| 8 — 設定の検索 | エンコーダーが含まれています。検索は、すべてのフィールドを約束するのではなく、設定カテゴリと一般的なキーワードとしてそのスコープを説明します。 |
| 9, 10 — セットアップとサインイン | セットアップフィールドでは、間隔を空けた垂直レイアウト、FlintEye のブランディング、および表示されるパスワード要件が使用されます。必須のサインインでは、遷移先のない「戻る (Back)」アクションが表示されません。 |
| 11, 12 — アクセシブルな状態とコントラスト | ナビゲーションは現在のページを公開し、カメラおよびマルチビューのセレクターは選択された状態を公開します。カメラコントロールは選択ボタンから分離されています。小さな PTZ の説明テキストのコントラストが強化されています。 |
| 14, 15 — ガイダンスと空の状態 | ガイドを開いても、まるでアクティブであるかのように別のページが装飾されることはなくなります。空のカメラ/出力/録画の状態では状況が説明され、空の録画リストではページネーションが省略されます。 |
<a id="physical-device-follow-up"></a>
## 物理デバイスのフォローアップ

その後の Windows/Mac/Linux のレビューにより、パッケージング、起動、およびシャットダウンに関する指摘事項が追加されました。修正、エビデンスの境界、および残りの受け入れチェックについては、[デバイス QA フォローアップ](DEVICE_QA_FOLLOWUP.ja.md)を参照してください。Windows のメディア子プロセスの終了と、macOS の Developer ID/公証は、引き続き明示的な制限事項です。

<a id="validation-and-remaining-limits"></a>
## 検証と残りの制限事項

回帰スイートでは、ビルド済みフロントエンド、Chromium、および合成 API 応答を使用します。遅延および失敗したリクエスト、下書きの保護、カメラの切り替え、キーボード操作、および狭いレイアウトを検証します。外部ホストへのリクエストをブロックし、物理カメラには接続しません。テストコマンドについては、[貢献ガイド](../.github/CONTRIBUTING.ja.md)を参照してください。

- **実機での受け入れ確認は引き続き必須です:** Windows および macOS のデスクトップの挙動、物理 USB/IP カメラ、PTZ の移動/停止、マイク/プライバシーの権限、スリープ/復帰、最小 OS のサポート、および実際の動画デコードは、対象のమachines（マシン）上で確認する必要があります。Linux のブラウザテストでは、すべてのブラウザやスクリーンリーダーとの互換性は確立されません。
- **競合する設定は自動的に統合されません:** 競合が発生した場合、下書きは画面に残ります。下書きを明示的に破棄して最新の設定を再読み込みする前に、必要な変更内容をコピーしてください。
- **デプロイのガイダンスが異なります:** ブラウザを閉じてもモニタリングは実行され続けたままになります。デスクトップユーザーは **Stop monitoring and quit** を介してアプリを停止し、Docker/systemd ユーザーはサーバーサービスを停止します。
- **リリースステータス:** パブリックインストーラーと GHCR イメージは、Windows x64、M1 Mac、および Linux x64 での受け入れ確認と、対応するソース/ライセンスレビューを条件として制限されます。既存の Actions アーティファクトは開発ビルドであり、安定版ではありません。[受け入れチェックリスト](ACCEPTANCE.ja.md)を参照してください。

再現可能な新しい問題は、[Issues](https://github.com/noguhiro2002/FlintEye/issues) から報告してください。レポートから資格情報、セットアップトークン、プライベートカメラの URL、および個人の映像を削除してください。脆弱性については、[プライベートセキュリティチャネル](../.github/SECURITY.ja.md)を使用してください。
