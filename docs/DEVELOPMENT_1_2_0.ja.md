## 公開前に必要な承認 (Acceptance)

専用のプロファイル、記録フォルダ、コンテナボリュームを使用してください。既存のユーザー記録と設定は保持してください。正確なリリース、チェックサム、コミット、OS/CPU、ブラウザ、インストールパス、プロファイル、および手順を記録し、シークレットや個人的な映像は除外してください。

1. Windows x64: ワンコマンドおよびEXE。それぞれ、クリーンなプロファイル、設定済みの保持されたプロファイル、未完了のセットアップ、変更されたインストールディレクトリ、スペースや非ASCII文字を含むパス、古いcwdを使用します。期待されるセットアップとログイン、バンドルされたMediaMTX、実際のビデオ、記録の復号完了、および所有者によるQuitの確認を行います。
2. Windows削除: 実行中、記録中、停止中、重複エントリ、意図的に保持されたアンインストールデータハンドル、権限拒否、および再試行。関連のないプロセスを終了させずに、ロック保持者を特定します。プログラム/プロセス/スタートアップ/所有するファイアウォールの残骸がなく、記録が保持されていることを確認します。所有者の元の症状をテストしてください。合成再現は所有者の環境での回復を証明するものではありません。
3. ネイティブMac M1、Windows x64、Linux: Open/Start/Stop/Restart/Quitの実際のトレイ/メニュークリック、ログイン時のスタートアップ、正しいアイコン、および表示される状態テキスト。VoiceOver/Narratorおよびキーボードは、ブラウザ内のパスワード入力と操作に到達可能でなければなりません。3つのOSファミリーすべてで、x64/ARM64のビルドとスモークテストを実行してください。
4. 物理LAN: Windows Edge/Chrome、Mac Safari/Chrome、Linux Firefox/Chrome、iPhone/iPad Safari、Android Chrome。インストール/削除の信頼性、管理者/ビューアの役割、初期所有権、ライブ/マルチビュー、記録/再生、同一URLでのアプリ/OS再起動。証明書のローテーション/有効期限、IP変更、複数のNIC、ファイアウォールによる拒否、不正な範囲、トークンの有効期限切れ/再利用、レート制限をテストします。実際のデバイス/OS/ブラウザのバージョンを記録してください。
5. 実際のUSBカメラ: 両方の接続デバイス、同時記録、取り外し/再接続、スリープ/復帰、24時間稼働、ストレージのフル/利用不可状態。急な停止/電源喪失のシミュレーションには使い捨てのテストデータとVMを使用します。完了したファイルが再生可能であり、不完全なファイルが誤って終了処理されていないことを確認してください。
6. Linux専用ホスト: 実際のapt/rpmインストール、更新と削除、SSH設定/正常終了、およびsystemdの開始/停止。Docker Engine: 公開されたイメージ、永続性、SIGTERMによる記録のフラッシュ、およびプロセスクリーンアップ。Docker Desktop: ホストブラウザ認証と実際のWebRTC再生。VM内部の健全性チェックだけでは不十分です。

## ビルド、レビュー、ロールバック

Pythonスイート、フロントエンドビルド/ブラウザスイート、ドキュメントチェック、および正確なネイティブパッケージ/コンテナのスモークテストを実行してください。シークレットや映像はコミットされたエビデンスの外に置いてください。ソースのみの単体テストやエミュレータは、必要なハードウェア承認の代わりにはなりません。Terraは、変更された認証とライフサイクルの境界をレビューします。

移行前に、ランタイム/監視のバックアップをプロファイル内の `backup-before-1.2.0` にプライベートで保存します。これらには機密設定が含まれているため、決して課題（issue）に添付しないでください。一致する古いバックアップを復元し、固定された1.1.3パッケージを再インストールする前に、新しいアプリケーションを停止してください。既存の記録とインベントリを保持します。LANアクセスをロールバックする場合は、新しいWindowsファイアウォールルールと古いクライアントの信頼設定を削除してください。自動的なダウングレードやデータ消去は実行されません。
