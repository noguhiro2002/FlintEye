# Reading the release test results

| GitHub Actions job | Required result | Evidence |
| --- | --- | --- |
| Distribution checks · tests | Every registered business API operation must pass its access policy and have a successful response through the production handler with its authorization dependencies intact. Setup token renewal must return the instruction to use the server. The suite also checks errors including credential rotation, concurrent edits, invalid payloads, missing cameras and unavailable playback. | Download `api-coverage-audit`. The JSON includes tests and statuses per operation, tested error sites, and line and branch coverage. |
| Distribution checks · tests | Inventory Settings controls, literal choices and limits. Exercise saves, validation, effective values and camera configuration in Chromium against the real API. | Download `settings-coverage` for the inventory and browser results. The inventory lists related tests and physical checks for each control. A case assignment identifies where a control is covered or tracked. |
| Distribution checks · tests | An 8 MiB temporary volume reaches ENOSPC. Cleanup frees space from an indexed segment, preserves an unfinished segment and an unrelated file, and the index accepts a new completion after the root returns. | The storage-fault step runs in a network-isolated container. This checks the storage and indexing code. |
| Distribution checks · tests | Compose initializes accounts on preview.3, reads the same volume with the candidate image and boots the old image with a backup taken while stopped. Both accounts, the stopped preference, playback and the original downloaded clip hash must survive. | The Compose step logs the tested release for each of its three phases. |
| Distribution checks · tests | Firefox and WebKit exercise setup, monitoring, recordings, conflicting setting revisions, dialog focus and navigation. Chromium runs the wider frontend suite. | Browser step logs. These frontend regressions use synthetic API responses. |
| Build release and published installation lifecycle | Add, rename and remove cameras, update path references, and select PTZ after inspecting a synthetic ONVIF camera. Live cameras and individual and composite recordings must contain content from the expected sources. The enabled camera must record its own 440 Hz tone in Standard format. The second camera must produce video with zero audio tracks. A browser download must match the SHA-256 of the clip selected in the UI. Linux GUI script cases also wait for the installer to start the app itself. | The lifecycle artifact includes browser receipts, ONVIF SOAP operations, the selected download, retained file hashes and `decode.log`. |
| Build release and published installation lifecycle | Configure event recording in the installed app, submit a synthetic equipment event with its dedicated token, and play and download the requested clip. Uninstall and reinstall before replaying the same clip. | The lifecycle artifact contains the event selection, downloaded clip and SHA-256 of the retained copy. |
| Distribution checks and native macOS build | Trigger a failed write during the shell installer download, verify its diagnostic and retry. Check Linux system/user modes and the macOS script. | Installer fault tests use an isolated file size limit and a local synthetic package. |
| Distribution checks | Verify ONVIF recovery after a connection reset, delayed and missing audio input, WebRTC audio fallback, both compositors, API key capabilities and revocation, and the active CA fingerprint in the iOS configuration profile. Exercise the iPhone guide, compact camera audio and aligned RTSP URL fields in a browser. | Backend contract evidence and browser job logs. |
| Build release and published installation lifecycle | Issue and revoke REST API keys from Settings. Decode two and three-camera Multiview frames with audio enabled, move inputs by drag and by selection, and compare the resulting position and live source list. Switch recording tabs and confirm the retained key metadata after reinstall. | Browser receipts, screen captures and decoded media. [Preview 8 findings and Preview 9 regressions (Japanese)](PREVIEW_8_FINDINGS.ja.md) |
| Build release · desktop | Exercise shutdown with a request in progress, ownership of child processes, macOS menu dispatch and Force quit confirmation outcomes. | The native process ownership and application quit step lists pass and skip results for each OS. |
| Build release · macOS bundle smoke | Test direct Stop during an open recording and Recording Off followed by Stop. Both cases must finalize real synthetic footage, clear recording counts and stop the media process. | The frozen-app smoke log identifies both tests. First-launch approval and physical camera behavior have their own device checks. |
| Build release · containers | Scan the exported amd64 and arm64 candidate archives. A fixed-version High or Critical advisory fails the job. Database or scanner errors also fail it. Findings without a published fix are retained for review. | Download `container-advisories-amd64` and `container-advisories-arm64`. These scans cover components identifiable in the Linux images. |

The [installed application test guide](../INSTALLATION_QA.md) explains manual-required results. Use the [device checklist](../RELEASE_CHECKLIST_1_2_0.md) for camera hardware, OS permissions, LAN clients and continuous operation. The Compose upgrade covers a single pinned predecessor. Native upgrade interruptions, remaining failure branches and long-running audio/video synchronization require separate evidence.
