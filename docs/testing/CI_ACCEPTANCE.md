# Reading the release test results

| GitHub Actions job | Required result | Evidence |
| --- | --- | --- |
| Distribution checks · tests | Every registered business API operation returns an HTTP response in the suite. New operations must have a reviewed access policy. Anonymous clients must be denied every protected operation, and viewers must be denied every administrator operation. Tests also check credential rotation, concurrent edits, recording filters and missing cameras. | Download `api-coverage-audit`. Each operation lists the tests and observed statuses. A denial counts as a response. Use the success-status and explicit-error-site columns to assess functional coverage. |
| Distribution checks · tests | An 8 MiB temporary volume reaches ENOSPC. Cleanup frees space from an indexed segment, preserves an unfinished segment and an unrelated file, and the index accepts a new completion after the root returns. | The storage-fault step runs in a network-isolated container. This checks the storage and indexing code. |
| Distribution checks · tests | Compose initializes accounts on preview.3, reads the same volume with the candidate image and boots the old image with a backup taken while stopped. Both accounts, the stopped preference, playback and the original downloaded clip hash must survive. | The Compose step logs the tested release for each of its three phases. |
| Distribution checks · tests | Firefox and WebKit exercise setup, monitoring, recordings, conflicting setting revisions, dialog focus and navigation. Chromium runs the wider frontend suite. | Browser step logs. These frontend regressions use synthetic API responses. |
| Build release and published installation lifecycle | Live cameras must show their own visual markers. Individual recordings and the two-tile composite must contain moving video with the correct source in each position. The enabled camera must record its own 440 Hz tone in Standard format. The second camera must produce video with zero audio tracks. A browser download must match the SHA-256 of the clip selected in the UI. Linux GUI script cases also wait for the installer to start the app itself. | The lifecycle artifact contains browser receipts, the selected path and download, the retained file hashes, and frame counts in `decode.log`. |
| Build release · containers | Scan the exported amd64 and arm64 candidate archives. A fixed-version High or Critical advisory fails the job. Database or scanner errors also fail it. Findings without a published fix are retained for review. | Download `container-advisories-amd64` and `container-advisories-arm64`. These scans cover components identifiable in the Linux images. |

The [installed application test guide](../INSTALLATION_QA.md) explains manual-required results. The [device checklist](../RELEASE_CHECKLIST_1_2_0.md) covers camera hardware, native permissions, LAN clients and continuous operation. A hosted-runner pass cannot close those items. The Compose upgrade covers a single pinned predecessor. Native upgrades and interrupted updates, all permitted API behavior and failure branches, and continuous audio/video synchronization still need separate evidence.
