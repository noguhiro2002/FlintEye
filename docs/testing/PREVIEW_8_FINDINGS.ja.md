# Preview 8 の検証で見つかった問題と Preview 9 の修正

画面と映像・音声の検証には macOS を使った。Preview 8 をワンコマンドのスクリプトでインストールした環境で発生した問題を記録する。Ubuntu では、システム全体とユーザー単位の両方でダウンロード中にエラーが出た。

| Preview 8 で確認したこと | Preview 9 での対応 | 回帰テスト |
| --- | --- | --- |
| Ubuntu の通常インストールは約77%、`--user` は約82%で止まり、`curl (23)` が出た。転送先に書き込めなかったことはログで確認できた。空き容量、クォータ、ファイルサイズ上限のどれが原因かは記録から特定できない。 | 共通のシェルインストーラーが取得できる場合はダウンロード前にサイズを確認する。書き込み失敗時は作業先と空き容量を示し、`TMPDIR` を指定して再試行できるようにする。 | 通常・ユーザー単位の Linux と macOS の共通処理で、事前判定、途中での書き込み失敗、後片付け、設定・録画の保持、再試行を確認する。 |
| **Enable PTZ** が選択済みでも、Live View に **ONVIF PTZ unavailable** が出た。ONVIF のサービス、プロファイル、PTZ ノードを照会するとき、相手側が接続を切断していた。 | Inspect camera と Live View が同じ方法で検出候補を確認する。接続先、認証、証明書、PTZ 機能の有無に応じて案内を出す。 | 接続リセット後の代替候補、Media1 と Media2、認証拒否、移動・停止を、合成 ONVIF 機器とブラウザーで確認する。 |
| IP カメラのライブ音声を有効にしたとき、MediaMTX の入力に対する RTSP の `404` と、音声処理の終了コード `8` が繰り返された。 | 入力が映像と音声を公開するまで音声処理を待機させる。失敗後は再試行の間隔を延ばす。Live View は音声用ストリームの準備中もカメラ映像を使う。 | 入力待ち、音声トラックなし、処理の終了と間隔、WebRTC の映像フォールバックと音声受信を確認する。 |
| カメラ2台を選択した状態で、映像の一部が重複して3枠に映った。アプリを終了して起動し直した後、閲覧者と管理者の両方で2台表示に戻った。 | 公開カメラの入力を一意に扱い、内部の音声・変換ストリームが枠として加わらないようにする。自動配置で2台だけの場合は横並びにする。 | 音声を有効にした2台で、合成映像の2箇所に異なる映像が届くこと、余分な位置が黒いことを確認する。 |
| 別の再現時は、合成映像には正しく3台が映っていたが、一覧とカメラ数は2台だった。音声のエラーも同時に出ていた。 | 稼働中の合成処理が使っている入力と位置を管理者・閲覧者の一覧に反映する。 | 3台目を追加して表示数と各枠の映像を確認し、削除後は再起動操作なしで2台に戻ることを確認する。 |
| **Tile Count** とソース選択で構成を指定できたが、各カメラが映る位置を設定できなかった。 | **Settings → Multiview → Camera layout** で、ドラッグまたは順に選択して配置する。空き枠と配置順を保存し、配信・録画に適用する。 | ブラウザーでドラッグと選択、保存と再表示、3台の色・位置と空き枠、録画の作成を確認する。通常と同期コンポジターで同じ位置を使い、パスの変更・削除も確認する。 |
| IP カメラの **Camera audio** が大きく、接続設定が下に押し出された。 | 音声の有効化、確認、保存を小さなツールバーにまとめる。設定を変更した場合に保存ボタンを表示する。 | 幅320〜1440pxのブラウザーとインストール済みアプリで表示と音声設定の保存を確認する。 |
| **Loop recordings** と **Event recordings** の見た目が同じで、選択中の一覧が分かりにくかった。 | 選択中のボタンに背景色と下線を付け、読み上げにも選択状態を伝える。 | 両方向に切り替えたときの選択状態と描画色を確認し、イベント映像を再生・ダウンロードする。 |
| MediaMTX の **RTSP Base URL** 入力が隣の入力より縦に伸びていた。 | 説明文の有無にかかわらず、入力欄の高さと行頭をそろえる。 | 異なる幅の画面で **Internal RTSP Base URL** と入力欄の高さを比較する。 |
| LAN の HTTPS に iPhone から接続すると `ERR_CERT_AUTHORITY_INVALID` が出た。iPhone で信頼されていた CA は記録から確認できない。 | 稼働中の CA の指紋を表示し、再起動待ちの間は新しいガイドの書き出しを保留する。iPhone でのプロファイルのインストールと、ルート証明書への完全な信頼を同じ画面で案内する。 | CA の有無と更新前後の HTTPS 接続、iOS プロファイルと実際の証明書の一致、ガイドの表示・書き出し条件を確認する。 |
| REST API に使うキーの場所や権限が、Settings から分からなかった。 | **Settings → Runtime & access → API access** で、読み取り専用または監視操作を許可するキーを発行・失効できるようにする。キー本体は発行時に表示する。 | 認証なし、閲覧者、管理者、権限外のキー、失効済みキーを確認する。インストール済みのブラウザーから発行・失効し、再インストール後のキー一覧を確認する。 |

GitHub Actions ではローカルに生成した映像・音声・ONVIF 応答を使う。API と設定画面のテストに加え、配布物のインストール、録画、終了、アンインストール、設定を保持した再インストールまでを確認する。検証で使った実カメラの接続情報・認証情報・映像はローカルに保管する。[自動テストの一覧と確認方法](CI_ACCEPTANCE.md)

macOS の初回起動時の承認、カメラのマイクや PTZ の動作、iPhone の設定アプリでの証明書のインストールは実機で確認する。[インストールと実機検証](../INSTALLATION_QA.ja.md) [LAN 接続と証明書の手順](../LAN_ACCESS.ja.md)

## Preview 9 の配布前検証で見つかった問題

Linux ARM64 の RPM をユーザー権限で再インストールした直後、録画台帳の更新と重なったイベント録画の一覧・再生で HTTP 503 が出た。既存の台帳を読むときはデータベースの初期化を省き、一時的なロックの解除を待つようにした。台帳を書き込み中の状態にして、解除後に一覧の表示と録画の取得ができることをテストする。

Windows x64 の EXE で録画一覧を開いた際に、サムネイルの要求がブラウザーの接続枠を使い、録画再生が始まらなかった。表示範囲のサムネイルを最大2件ずつ取得し、プレーヤーを開いた間は未完了の取得を止めるようにした。低速のサムネイル取得中にも再生要求が進み、プレーヤーを閉じると取得が再開することをテストする。

Live View から移動した際に、ブラウザーが途中で取り消した WebRTC の操作がサーバー例外として記録された。取り消された要求は MediaMTX へ送らず、再接続や通常の操作が続けられることを確認する。
