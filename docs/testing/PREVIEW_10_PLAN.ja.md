# FlintEye Preview 10 改修計画書

## 目的と完了条件

カメラを追加して録画・視聴を始めるまでの設定を簡素化し、PCとスマートフォンで映像や主要操作にすぐ届くようにする。LinuxのユーザーインストールでUSBが見えない問題、LAN/VPNと証明書の案内、テーマ切り替え、READMEのインストール手順も改修する。

対象は [Preview 9](https://github.com/noguhiro2002/FlintEye/releases/tag/v1.2.0-preview.9) の実装。画面調査では幅390 pxで長いイベント名によりページ幅が843 pxに広がった。3台構成のLive Viewでは幅1024 pxのPCで映像欄が上端から823 px、スマートフォンの縦向きで1,316 pxにあった。幅390 pxのSettingsではフォームに着くまでにカテゴリ一覧だけで約280 pxを使っていた。

## Settingsと初回案内

Settingsの初期表示は **Basic** とし、**Advanced** に切り替えられるようにする。

| 区分 | Basic | Advanced |
|---|---|---|
| カメラ | USBの検出と追加、IPカメラの追加、名前、接続確認、有効・無効。USBは推奨モードを初期値にし、対応を確認できたカメラで音声とPTZを設定する。 | USBプロファイル・内部パス・動画モードの個別指定、手動ONVIFとプロファイル、PTZ速度、リレー・タイムスタンプ・CFR、エンコード、Watchdog、音声の詳細設定。 |
| 録画 | 有効・無効、対象カメラ、合成映像の録画、保存先、容量上限、保持日数。必要なときに以前の保存先の表示設定。 | 自動適用、追加録画パス、形式、セグメント・パート、再生キャッシュ。機器連携の設定からイベント録画の保存先・遡る秒数・専用トークンを管理する。 |
| Multiview | 有効・無効、対象カメラ、レイアウト、配置プレビュー、画質プリセット。タイルはドラッグとタップで配置できる。 | ソース取得方式、追加パス、出力名、上限数、MediaMTX API・入出力URL、個別入力の正規化と画質、同期バッファー、遅延、監視・隔離・再接続・定期再起動。 |
| 接続・起動 | 視聴者ログインとパスワード、LAN/VPN、接続状態、起動時の監視再開、対応環境でのログイン時起動。 | API Host・Port、認証方式、セッション・サムネイル設定、MediaMTX、外部プレーヤー用RTSPS、証明書更新、ファイアウォール、REST APIキー。 |
| 共通 | 更新確認と診断情報はInformationから利用できる。録画から機器連携とAPIの設定へ移動できる。 | 表示名とフッター、ログ、Full Runtime JSON、全体の再起動。 |

両タブは同じ編集状態を使い、タブを切り替えても未保存の値を保持する。Basicから保存しても詳細設定の既存値を保持する。設定の競合検出と破棄確認を引き継ぐ。スマートフォンではカテゴリ選択を1行にし、保存・破棄は編集中に手元へ出す。カメラは一覧から1台を選んで編集し、追加時は新しい欄を開く。

設定検索はLAN、VPN、Tailscale、イベント録画、APIキーの英日表記から該当欄を開く。Getting startedのカメラ追加と録画先も該当欄を直接開く。初回案内の完了・スキップ後は、管理者がInformationから再開できる。画面右上のテーマアイコンから **システムに合わせる／ライト／ダーク** を選べる。初期値はシステムに合わせ、ブラウザーごとに選択を保持する。初回設定、ログイン、主要画面とダイアログも対象にする。

## LAN/VPNとUSB

LAN/VPNは既存のFlintEye CAを使う。初回設定で、保存後の再起動と閲覧端末でのCA登録が必要だと案内する。無効、保存済み・再起動待ち、接続可能、起動失敗を分けて表示し、再起動後にHTTPSリスナーが稼働してから共有先を示す。デスクトップ、ヘッドレス、systemd、Composeごとの通常の再起動手順を示す。Tailscale使用時はサーバーIPv4、許可範囲、公開CA・指紋の照合、端末の信頼設定と証明書エラーからの復旧を案内する。Settingsの「Connect an iPhone or iPad」は削除し、端末別の案内は接続ガイドに置く。

LinuxではユーザーインストールしたFlintEyeと同じ条件で、OSのUSB認識、撮影ノードへのアクセス、保存デバイス名、対応モードと映像受信を確認する。撮影用ノードとメタデータ用ノードを区別し、未検出、権限なし、使用中、撮影モード未取得を表示する。新規登録では、撮影ノードを一意に指せる場合にLinuxの安定したデバイスパスを使う。既存カメラの付け替えでは、確認操作を経てカメラID・配信パス・録画との関連付けを引き継ぐ。

## 検証と配布

- 日英READMEのLinux欄に、固定版のインストーラーを一時ファイルへ取得し、ダウンロード成功時だけユーザー権限で実行する1行を載せる。オンライン導入、取得失敗、オフライン成果物からの導入、削除とデータ保持を確認する。
- GitHub Actionsとプッシュ前の検証は共通のチェックを使う。チェックの抜け、失敗の伝播、未検証の扱いにもテストを設ける。設定全項目の一覧と実APIの往復、既存プロファイル、競合、権限、テーマ、初回案内を確認する。ChromiumとWebKitでPC幅1440・1024 px、モバイル幅320・390・430 pxと横向き844 × 390を確認する。
- 対象パッケージで新規導入・更新・終了・再インストールを検証する。名前変更、ONVIF PTZ、音声障害時の映像継続、2台・3台のMultiview、ループとイベント録画、APIキー、録画確定後の終了を回帰対象とする。
- 実機ではUSB 2台と指定のRIKEN VPNカメラで検出から録画再生まで確認する。別のPCとiPhoneで保存、再起動、CA信頼、HTTPS、映像を確認する。RIKENの接続情報・認証情報・実映像・画像・生ログはローカルに保管する。GitHub Actionsと公開ガイドは合成データを使う。
- 初心者役のE2Eを行い、導入から録画再生までの手順を画像入りガイドに反映する。自動検証と実機は、合格、失敗、未検証を記録する。既存テストと追加テストを通し、同じ変更のパッケージを検証して Preview 10 の公開候補とする。公開は別途承認を得て行う。
