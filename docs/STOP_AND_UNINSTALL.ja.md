# FlintEyeの停止とアンインストール

[English](STOP_AND_UNINSTALL.md) · [ドキュメント](README.ja.md) · [インストール](INSTALL.ja.md)

## 監視の停止

Windowsでは、FlintEyeの通知領域アイコン（隠しアイコンの矢印を確認してください）から**Stop monitoring and quit**を選択します。macOSでは、FlintEyeのメニューバーアイコンを使用します。Linuxでは、FlintEyeのデスクトップウィンドウ内のボタンを使用します。ブラウザを閉じたりサインアウトしたりしても、視聴セッションが閉じるだけで、監視は意図的に継続されます。

アップデートされたアプリケーションは、終了する前にカメラワーカー、FFmpeg/FFprobeタスク、MediaMTX、およびAPIを停止します。シャットダウン中の新規ワーカーの起動を防ぎ、ワーカーがすでに終了している場合でもその子プロセスをクリーンアップします。Windowsのメディア子プロセスは強制終了ジョブ（kill-on-close job）によって管理されているため、アプリがクラッシュした場合でもそれらの子プロセスは終了します。他のアプリケーションによって起動されたブラウザやメディアツールはそのジョブの対象外です。

FlintEyeのアイコンが消え、他のアプリが使用していなければカメラのインジケーターが消灯し、ローカルのFlintEye URLへの新しいリクエストが接続できなくなることを確認します。サーバー停止後も、以前に開いたブラウザページがメモリ上に表示されたままになることがあります。FlintEyeを再起動すると、保存された設定と録画が復元されます。

## Windows: アプリケーションのアンインストール

**Settings → Apps → Installed apps → FlintEye → Uninstall**を使用します。アップデートされたアンインストーラーは、まずインストールされたアプリに停止を要求し、その完了を待ってから、現在のWindowsユーザーに属するその特定のインストールからの残存プロセスを確認します。プログラムファイルを削除する前に、残っている同梱プログラムのプロセスをすべて停止します。それらが停止したことを確認できない場合は、Windowsを再起動してやり直せるように、エラーを出して削除が中断されます。

通常の場所は次のとおりです。

| 場所 | 内容 | 通常のアンインストール |
| --- | --- | --- |
| `%LOCALAPPDATA%\Programs\FlintEye` | アプリケーション、同梱されたPython/FastAPI、FFmpeg、FFprobe、MediaMTX、およびアンインストーラー | 削除されます |
| `%LOCALAPPDATA%\FlintEye` | アカウント、設定、ログ、録画インデックス、およびデフォルトの録画 | 保持されます |
| 別の場所に選択した録画フォルダ | 録画 | 保持されます |

FastAPIは同梱されたPythonアプリケーションの一部であり、デスクトップインストーラーによってインストールされる個別のWindowsサービスではありません。Python、FastAPI、FFmpegをグローバルにアンインストールする必要はありません。Windowsのログイン時起動エントリとショートカットはアプリと共に削除されます。オプションのデータ削除の確認プロンプトのデフォルトは**No**です。サイレントアンインストールでは常にデータが保持されます。外部の録画フォルダがこのアンインストーラーによって削除されることはありません。

## 古いWindows版で残ったプロセスへの対処

古いインストーラーでは、ランチャーの終了後または削除後もバックグラウンドプロセスが実行し続ける場合があります。それらのアンインストーラーには新しい停止手順が含まれていません。データフォルダを削除しても実行中のAPIは停止せず、設定や録画が失われます。

1. アイコンがまだ存在する場合は、**Stop monitoring and quit**を試してください。
2. 停止しない場合は、Windowsを再起動します。FlintEyeを再び開かないようにしてください。残存しているログインエントリによって再度起動してしまう場合は、**Settings → Apps → Startup**でFlintEyeのエントリを無効にしてから、再度再起動してください。
3. FlintEyeがInstalled appsにまだ表示されている場合は、アンインストールします。一覧に表示されなくなっている場合は、エクスプローラーで `%LOCALAPPDATA%\Programs` を開き、残っている **FlintEye** プログラムフォルダのみを削除してください。データを明示的に消去したい場合を除き、`%LOCALAPPDATA%\FlintEye` は保持してください。
4. 準備ができたら、修正済みパッケージを再インストールします。保持したデータを再利用できます。

古いインストールを再起動せずに停止したい管理者のために、更新されたソースには [stop_windows.ps1](../packaging/stop_windows.ps1) が含まれています。確認済みのローカルスクリプトを同じWindowsユーザーとして実行し、必要に応じてインストールフォルダを調整してください。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\packaging\stop_windows.ps1 -InstallDir "$env:LOCALAPPDATA\Programs\FlintEye"
```

この呼び出しは、そのPowerShellプロセスに対してのみ実行ポリシーを変更します。このヘルパーは実行ファイルのパスと所有権を確認しますが、ファイルの削除は行いません。その後もAPIが応答する場合は、そのポートでリッスンしているプロセスを特定してください。別のインストール、手動で起動されたサーバー、Docker、またはキャッシュされたページの可能性があります。すべての `python.exe` または `ffmpeg.exe` プロセスを無差別終了しないでください。

## macOSおよびLinux

アプリを置き換えるか削除する前に、監視を停止してください。macOSではインストールされた `FlintEye.app` を削除し、Linuxではパッケージマネージャーを通じてパッケージを削除します。データを意図的に消去する場合を除き、[録画のライフサイクル](DISTRIBUTION.ja.md#recording-lifecycle) に記載されているデータディレクトリは保持してください。手動で設定されたsystemdサービスやDockerコンテナは個別に管理されるため、独自のデプロイツールを通じて停止する必要があります。

## どのビルドにこの変更が含まれていますか？

これらの修正には、再ビルドされたインストーラーが必要です。以前にダウンロードした 1.1.0/1.1.1 インストーラーは変更されていません。ローカルビルドでは引き続き 1.1.1 と報告されるため、ビルド情報内のソースコミットを確認してください。[M1向けビルド手順](LOCAL_MACOS_BUILD.ja.md) は、GitHub Actionsを使用せずに、現在コミットされているソースをビルドします。

自動テストでは、所有プロセスのクリーンアップ、子プロセスが生存している状態で終了したワーカー、Wine環境下でのWindowsジョブの所有権、およびインストール済みバンドルのシャットダウン要求がカバーされています。Wineは実際のWindowsアンインストールテストの代わりにはなりません。各ターゲットデバイスで終了、カメラの解放、再起動を確認し、無関係なアプリケーションが実行され続けていること、およびアンインストールによってアカウントと録画が保持されることを確認してください。

macOSでは、Dockからの通常の「終了」アクションもこのシャットダウンシーケンスを経由します。「強制終了」およびオペレーティングシステムによる強制終了は別ケースであり、カメラの解放をテストする際は通常の「終了」パスを使用する必要があります。
