# FlintEyeの停止とアンインストール

[English](STOP_AND_UNINSTALL.md) · [Documentation](README.ja.md) · [Installation](INSTALL.ja.md)

インストール方法を選択してアプリケーションのシャットダウンを完了し、その後アプリケーションを削除してください。再インストール時のためにデータを保持するか、データを削除したい場合にのみ[明示的なデータ消去](#permanently-erase-data-optional)に従ってください。

<a id="remove-by-installation-method"></a>
## インストール方法別の削除

**意図的に消去しない限り、アカウント、設定、録画は保持されます。** 1コマンドのインストーラーは、バイナリインストーラーと同じネイティブアプリケーションをインストールします。そのバンドルされたPython/FastAPI、FFmpeg、FFprobe、およびMediaMTXはアプリケーションと共に削除されます。他のソフトウェアで使用されているシステム全体のコピーは削除しないでください。

| インストール方法 | 停止と削除 |
| --- | --- |
| Windowsスクリプト / EXE / Actionsパッケージ | [Windows](#windows-uninstall-the-application)を参照：終了後、Windowsの設定からアンインストールします。 |
| macOSスクリプト / Actions `install.sh` | [macOS](#macos)を参照：ログイン起動を無効化して終了し、`~/Applications/FlintEye.app` またはカスタムインストール先を削除します。 |
| macOS DMG / ローカルビルドDMG | [macOS](#macos)を参照：ログイン起動を無効化して終了し、`/Applications/FlintEye.app` またはドラッグしたコピーを削除します。 |
| Linuxスクリプトの `--user` | FlintEyeを終了し、ダウンロードしたスクリプトで `bash ./install.sh --user --uninstall` を実行します。[ユーザー単位の導入と削除](../README.ja.md#install-without-administrator-privileges) |
| Linuxスクリプト / DEB / RPM | [Linuxパッケージ](#linux-packages)を参照：ログイン起動を無効化して終了し、apt-getまたはdnfでパッケージを削除します。 |
| Docker Engine / Docker Desktop / 開発用Compose | [Docker Compose](#docker-compose)を参照：インストール時に使用したComposeファイルとプロジェクトでコンテナを停止/削除します。 |
| systemd | [systemd](#systemd)を参照：ユニットとアプリケーションを削除する前にサービスを停止・無効化します。 |
| 手動ソース / 仮想環境 | [ソースの削除](#manual-source-and-virtual-environment)を参照：すべてのソースプロセスを停止し、専用環境を削除する前にチェックアウト内のデータを保持します。 |

`docker compose down` は名前付きボリュームを保持します。データを削除する意図がない限り、`--volumes` / `-v` を追加しないでください。ダウンロードしたインストーラーやActionsのZIPファイルも個別に削除可能です。`/Applications/FlintEye.app` と `~/Applications/FlintEye.app` の両方が存在する場合は、これらは別々のコピーです。アクティブな方を終了し、不要になった各コピーを削除してください。検証中に古いコピーを起動しないように注意してください。

<a id="stop-monitoring-and-quit"></a>
## Stop monitoring and quit

完全に終了するには、WindowsではFlintEyeの通知領域アイコン（隠しアイコンの矢印をご確認ください）から **Quit FlintEye** を選択します。macOSではFlintEyeのメニューバーアイコンを使用します。LinuxではコンパクトなFlintEyeコントロールウィンドウを使用します。**Stop monitoring** は設定とAPIを利用可能な状態にしたままカメラや録画を一時停止し、**Start monitoring** で再開します。[ステータスカラー、録画のファイナライズ、および起動時の設定](MONITORING.ja.md)。ブラウザを閉じたりサインアウトしたりしても、閲覧セッションが閉じるだけであり、意図的にモニタリングは実行されたままになります。

更新されたアプリケーションは、終了する前にカメラワーカー、FFmpeg/FFprobeタスク、MediaMTX、およびAPIを停止します。停止中の新しいワーカーの起動を防ぎ、ワーカーがすでに終了している場合でも子プロセスをクリーンアップします。Windowsのメディアの子プロセスは終了時killジョブによって所有されているため、アプリがクラッシュした場合でもそれらの子プロセスは終了します。他のアプリケーションによって起動されたブラウザやメディアツールはそのジョブの一部ではありません。

FlintEyeアイコンが消え、他のアプリが使用していなければカメラインジケータが消灯し、ローカルのFlintEye URLへの新規リクエストが接続されなくなることを確認してください。サーバー停止後も、以前に開いたブラウザページがメモリから表示されたままになる場合があります。FlintEyeを再起動すると、保存された設定と録画が復元されます。

<a id="windows-uninstall-the-application"></a>
## Windows: アプリケーションのアンインストール

通知領域アイコンから **Quit FlintEye** を選択し、お使いのWindowsのバージョンに応じた手順を実行してください。

- **Windows 11:** **設定 → アプリ → インストールされているアプリ → FlintEye → アンインストール**
- **Windows 10:** **設定 → アプリ → アプリと機能 → FlintEye → アンインストール**

削除が完了するまで待機してください。アンインストーラーは通常のアプリケーション終了と録画の完了を要求し、インストールに関連する残存プロセスやロックを確認した上でプログラムファイルを削除します。停止やロックの確認に失敗した場合は削除がキャンセルされます。表示される復旧手順に従って再試行してください。アカウント、設定、録画を保持するために、データ削除の質問にはデフォルトの **No** を選択してください。このインストールによってファイアウォールルールが作成された場合、プロンプトが表示されたら削除を承認してください。

通常の保存場所は次のとおりです。

| 場所 | 内容 | 通常のアンインストール |
| --- | --- | --- |
| `%LOCALAPPDATA%\Programs\FlintEye` | アプリケーション、バンドルされたPython/FastAPI、FFmpeg、FFprobe、MediaMTX、およびアンインストーラー | 削除されます |
| `%LOCALAPPDATA%\FlintEye` | アカウント、設定、ログ、録画インデックス、およびデフォルトの録画 | 保持されます |
| 別途選択した録画フォルダ | Recordings | 保持されます |

FastAPIはバンドルされたPythonアプリケーションの一部であり、デスクトップインストーラーによってインストールされる個別のWindowsサービスではありません。Python、FastAPI、またはFFmpegをグローバルにアンインストールする必要はありません。このインストールのWindowsのログイン起動エントリとショートカットはアプリと共に削除されますが、別のインストールを指す登録は保持されます。ログイン時の起動は、サイレントインストーラーではなく、最初のセットアップ後にデスクトップアプリによって登録されます。オプションのデータ削除の質問のデフォルトは**No**であり、サイレントアンインストールでは常にデータが保持されます。外部の録画フォルダがこのアンインストーラーによって削除されることはありません。

<a id="recover-an-older-windows-installation"></a>
## 以前のWindowsインストールの修復

古いインストーラーでは、ランチャーの終了後や削除後もバックグラウンドプロセスが実行し続ける可能性があります。それらのアンインストーラーには新しい停止手順が含まれていません。データフォルダを削除しても実行中のAPIは停止せず、設定や録画が破損する可能性があります。

1. アイコンがまだ存在する場合は、**Quit FlintEye** を試してください。
2. 停止しない場合は、Windowsを再起動します。FlintEyeの再開は避けてください。残存しているログインエントリによって再度起動された場合は、**設定 → アプリ → スタートアップ**でFlintEyeのエントリを無効にしてから、再度再起動してください。
3. FlintEyeが「インストールされているアプリ」(Windows 11) または「アプリと機能」(Windows 10) にまだ表示されている場合は、アンインストールします。表示されなくなっている場合は、エクスプローラーで `%LOCALAPPDATA%\Programs` を開き、残っている **FlintEye** プログラムフォルダのみを削除してください。データを明示的に消去したい場合を除き、`%LOCALAPPDATA%\FlintEye` は保持してください。
4. 準備ができたら、修正されたパッケージを再インストールします。保持されたデータは再利用できます。

再起動せずに古いインストールを停止したい管理者のために、更新されたソースには [stop_windows.ps1](../packaging/stop_windows.ps1) が含まれています。レビュー済みのローカルスクリプトを同じWindowsユーザーとして実行し、必要に応じてインストールフォルダを調整してください。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\packaging\stop_windows.ps1 -InstallDir "$env:LOCALAPPDATA\Programs\FlintEye"
```

この呼び出しは、そのPowerShellプロセスに対してのみ実行ポリシーを変更します。ヘルパーは実行ファイルのパスと所有権を確認しますが、ファイルの削除は行いません。`--data-dir` 引数を検出し、選択されたインストール内の各カレントユーザーインスタンスに対して正常終了を要求します。1つのプロファイルを対象にするには、`-DataDir "C:\path\to\profile"` を追加します。これにより、環境変数を通じて選択されたプロファイルも処理されます。`-Force` がない場合、タイムアウトはエラーになります。タイムアウト後に一致するプロセスを強制終了する意図がある場合にのみ、`-Force` を使用してください。更新されたアンインストーラーは通常の終了を要求し、停止が不完全な場合はキャンセルされます。自動的に強制フォールバックを選択することはありません。

選択されたデータディレクトリ内の `last-stop-result.json`（またはインストール全体での停止の場合は `%LOCALAPPDATA%\FlintEye`）は、`already-stopped`、`requested-shutdown-completed`、`forced`、および `incomplete` を区別します。終了コード0は選択されたプロセスが消えたことを意味し、終了コード1は停止が不完全であったことを意味します。別の `last-monitoring-stop.json` 確認記録には、録画の完了と保留中/強制終了の結果が記録されます。Windowsヘルパーは、停止要求後に作成された確認記録を `media_finalization` レポートに組み込みます。見つからない確認記録や古い確認記録は検証されないままになります。プロセスの終了単体では録画の完了を証明しません。録画中の停止をテストする際は、最後の録画と録画インデックスを確認してください。その後もAPIが応答する場合は、そのポートでリッスンしているプロセスを特定してください。それは別のインストール、手動で起動されたサーバー、Docker、またはキャッシュされたページである可能性があります。`python.exe` や `ffmpeg.exe` のプロセスを無差別に終了させないでください。

<a id="macos-and-linux"></a>
<a id="macos"></a>
## macOS

これらの手順は、Apple SiliconおよびIntel Mac（ローカルビルドのDMGを含む）に適用されます。まずFlintEyeメニューバーアイコンから **Disable start at login and quit** を選択し、アイコンが消えるのを待ちます。Finderで **移動 → フォルダへ移動** を選択し、該当するフォルダを開いてアプリをゴミ箱に移動します。

| インストール | 削除対象のフォルダ/ファイル |
| --- | --- |
| 1コマンドインストーラーまたは `install.sh` | `~/Applications/FlintEye.app`。`--install-directory` を指定した場合は選択したフォルダを使用してください。 |
| ダウンロードまたはローカルビルドDMG | `/Applications/FlintEye.app`、またはドラッグした保存先。 |
| スクリプトによって保持された旧コピー | ロールバックが不要であれば、同じフォルダ内の `FlintEye.previous.app`。 |

マウントされているFlintEye DMGがあれば取り出し、ダウンロードしたDMG/ZIPは不要であれば削除してください。ダウンロードを削除するだけではインストール済みのアプリは削除されません。両方のアプリケーションフォルダにコピーが存在する場合は、ログイン起動を無効にした後、それぞれの不要なコピーを削除してください。

macOSでは、`FlintEye.app` をゴミ箱に移動する前に、FlintEyeのメニューバーアイコンから **Disable start at login and quit** を選択してください。これにより、現在のインストール/プロファイルに属している場合に `~/Library/LaunchAgents/community.flinteye.plist` が削除され、そのログイン登録が解除され、自動起動が無効になっていることが記憶されます。この明示的な操作により、共有バンドルIDのみを使用していた古いデフォルトプロファイルの登録を削除することもできます。自動起動は、そのあいまいなレガシーエントリを置き換えるものではありません。アプリをゴミ箱にドラッグするだけでは、アンインストーラーは実行されず、LaunchAgentも削除されません。

アプリがすでに停止している場合は、削除前にログイン起動を無効にしてください。1コマンドインストールの場合は以下を実行します：

```sh
"$HOME/Applications/FlintEye.app/Contents/MacOS/FlintEye" --disable-autostart
```

システムアプリケーションフォルダにコピーされたDMGの場合は、代わりに以下を実行します：

```sh
/Applications/FlintEye.app/Contents/MacOS/FlintEye --disable-autostart
```

別の場所にインストールされている場合はアプリのパスを調整し、カスタムプロファイルの場合は `--data-dir` を追加してください。このコマンドはログイン時の起動のみを変更するものであり、実行中の別のインスタンスを停止したり、設定や録画を削除したりするものではありません。後でログイン時の起動を復元するには、同じアプリを `--enable-autostart` 付きで実行します。新しいMacの登録は、インストールされた特定のアプリのコピーを対象とします。一時的なApp Translocationのパスは登録されないため、最初にアプリを「アプリケーション」フォルダに移動してください。別のインストール/プロファイルが所有する登録は保持され、有効化コマンドは置き換える代わりに失敗を報告します。アプリがすでに削除されている場合は、上記のFlintEye LaunchAgentのみを削除してから、ログアウトして再度ログインし、起動しなくなったことを確認してください。

<a id="linux-packages"></a>
## Linuxパッケージ

1コマンドインストーラーは、お使いのディストリビューションのDEBまたはRPMパッケージマネージャーを使用します。手動で開いたパッケージ（ARM64 Raspberry Pi用パッケージを含む）も同じ削除手順が適用されます。

1. FlintEyeで **Start at login** を無効にし、**Quit FlintEye** を選択してカメラ/録画のシャットダウンを待ちます。サービスを設定した場合は、[先に停止して無効化してください](#systemd)。
2. インストールしたパッケージ形式に対応するコマンドを実行します。

**Ubuntu / Debian / Raspberry Pi OS — DEB:**

```sh
sudo apt-get remove flinteye
```

**Rocky Linux / AlmaLinux / RHEL — RPM:**

```sh
sudo dnf remove flinteye
```

アプリがすでに停止している場合は、`/opt/flinteye/FlintEye --disable-autostart` でパッケージ削除前にログインエントリを無効にできます。デスクトップユーザーとして（sudoなしで）実行してください。カスタムプロファイルを使用した場合は `--data-dir` を追加します。パッケージがすでに削除されている場合は、それが別のインストールを指していないことを確認した上で、このインストールの残存ファイル `~/.config/autostart/flinteye.desktop` のみを削除してください。ユーザーデータと外部の録画フォルダは保持されます。

<a id="docker-compose"></a>
## Docker Compose

元のデプロイメントディレクトリまたはチェックアウトのルートから、対応するコマンドを実行します。インストール時に使用したComposeファイル、`.env`、プロジェクト名、および `-p` / `--project-name` や `--env-file` オプション（これらがコンテナとボリュームを識別します）を同じ状態で使用してください。

| デプロイメント | 作業ディレクトリ | コンテナの停止と削除 |
| --- | --- | --- |
| Linux Docker Engine (ダウンロードした `compose.yaml`) | ダウンロードしたファイルと `.env` があるフォルダ | `docker compose down` |
| Docker Desktop (ダウンロードした `compose.desktop.yaml`) | ダウンロードしたファイルと `.env` があるフォルダ | `docker compose -f compose.desktop.yaml down` |
| ソースからビルドしたLinux Docker Engine | チェックアウトルート | `docker compose down` |
| ソースからビルドしたDocker Desktop | チェックアウトルート | `docker compose -f deploy/compose.desktop.yaml down` |
| 開発用イメージ | チェックアウトルート | `docker compose -f deploy/compose.dev.yaml down` |

録画の終了処理のため、コマンドが完了するまで待ってください。これにより、FastAPI、FFmpeg、MediaMTXを含むコンテナとその所有プロセスが削除されます。名前付きボリュームとバインドマウントされた録画は残ります。通常のアンインストールでは `--volumes` / `-v` を追加しないでください。

ダウンロードしたイメージは `down` 後もキャッシュに残ります。領域を解放するには、必要に応じて使用したFlintEyeイメージのみを削除してください（例: `docker image rm ghcr.io/noguhiro2002/flinteye:1.2.0-preview.10`、開発用イメージの場合は `docker image rm flinteye:development`）。バージョンはインストール済みのタグに合わせて調整してください。他のコンテナで使用されている場合は強制削除しないでください。Docker自体や他のアプリケーションで使用されているイメージ/レイヤーはインストールされたままになります。Composeファイルと `.env` は再インストール時のために保持し、デプロイメント定義が不要になった場合のみ削除してください。

<a id="systemd"></a>
## systemd

サーバーガイドに沿ったシステムサービスの場合：

```sh
sudo systemctl disable --now flinteye
```

シャットダウンを待ちます。手動でインストールした `/etc/systemd/system/flinteye.service` と、このサービス用に作成したドロップインファイルを削除し、systemdを再読み込みします：

```sh
sudo systemctl daemon-reload
```

DEB/RPMをインストールした場合は、[パッケージマネージャー](#linux-packages)からアプリケーションを削除してください。`/opt/flinteye` にバンドルを手動で展開した場合は、内部に保存したデータを保持した上で、専用のプログラムフォルダのみを削除してください。`/var/lib/flinteye`、カスタムデータディレクトリ、外部録画フォルダは再利用のために保持してください。ユーザーサービスの場合は `systemctl --user disable --now YOUR_UNIT.service` を使用し、実際のユーザーユニット/ドロップインの削除と `systemctl --user daemon-reload` を実行してください。設定した名前と場所を使用してください。デスクトップインストーラーは自動的にシステムサービスを作成しません。

<a id="manual-source-and-virtual-environment"></a>
## ソースの削除と仮想環境

このルートはWindows、macOS、Linuxでのソース実行に適用されます。ソースランチャーが利用可能な間に、デスクトップのログイン起動を無効にしてください。**Quit FlintEye** でデスクトップランチャーを停止するか、API、フロントエンド開発サーバー、スタンドアロンツールを実行している各ターミナルで Ctrl+C を押して終了を待ちます。systemdやComposeで起動している場合は、先にそのデプロイメントの停止/削除手順を実行してください。

`.env`、`runtime.json`、録画、およびチェックアウト内に保持しているカスタムデータをバックアップします。`deactivate` で仮想環境を無効化し、ファイルマネージャーを使用して専用のFlintEyeチェックアウトと仮想環境のみを削除してください。これにより `node_modules` と生成されたフロントエンドファイルも削除されます。チェックアウト外で作成された環境は別途削除が必要です。デフォルトのデスクトップデータフォルダは再インストール時のためにそのまま残ります。

FlintEyeはpipアプリケーションパッケージとしてインストールされません（`requirements.txt` が依存関係をインストールします）。`pip uninstall flinteye` を削除手順として使用したり、他のソフトウェアで使用されている共有のPython、Node.js、FFmpeg、MediaMTXを削除しないでください。手動で設定したソースの自動起動エントリは、このインストールに属している場合のみ削除してください。

<a id="permanently-erase-data-optional"></a>
## 明示的なデータ消去（オプション）

**これは通常のアプリケーション削除とは別個の処理であり、アカウント、設定、ログ、録画を永久に削除します。** 必要なものをバックアップし、選択したデータを使用しているすべてのインスタンスを停止し、開始前に起動設定を無効にしてください。再インストール時のために設定を残したい場合は、これらの場所をそのままにしておいてください。

| インストール | 通常の削除後に保持されるデータ |
| --- | --- |
| Windowsデスクトップ | `%LOCALAPPDATA%\FlintEye`。アンインストーラーの個別の削除質問はデフォルトで **No** です。このデフォルトフォルダを消去したい場合にのみ **Yes** を選択するか、終了後に保持されたフォルダをエクスプローラーで削除してください。サイレント削除では常に保持されます。 |
| macOSデスクトップ | `~/Library/Application Support/FlintEye`。Finderの **移動 → フォルダへ移動** で開き、消去の意図がある場合のみFlintEyeデータフォルダをゴミ箱に移動してください。 |
| Linuxデスクトップ | `~/.local/share/flinteye`、または `XDG_DATA_HOME` が設定されている場合は `$XDG_DATA_HOME/flinteye`。終了後、選択したFlintEyeフォルダのみを削除してください。 |
| systemd | `/var/lib/flinteye`（別のデータディレクトリを設定した場合を除く）。消去の意図がある場合は管理者が別途削除する必要があります。 |
| Docker | `/data` にマウントされた名前付きボリューム、および別途バインドマウントされた録画フォルダ。 |
| カスタムソースまたはデスクトッププロファイル | `--data-dir` や `FLINTEYE_DATA_DIR` で選択したディレクトリ、および外部録画フォルダ。 |

外部の録画場所とカスタムプロファイルは、Windowsアンインストーラーによるデフォルトフォルダ削除の対象外です。削除前に個別に検査してください。Dockerの場合、一致する `down` コマンドに `--volumes` を追加すると、プロジェクトのCompose管理対象名前付きボリュームが明示的に削除されます。バインドマウントされたホストフォルダや外部ボリュームは削除されません。特にComposeファイルに他のサービスが含まれている場合は、プロジェクトとボリュームの内容を最初に確認してください。広範な `docker prune` コマンドの使用は避けてください。

### 残留起動設定とLAN信頼の削除

[macOS](#macos)、[Linux](#linux-packages)、または[以前のWindows修復](#recover-an-older-windows-installation)の手順を使用して、残っている起動登録を削除してください。削除するFlintEyeに属する起動設定だけを削除してください。systemdやDockerの場合、そのデプロイメントの無効化/削除はデスクトップのログイン起動とは別個です。

サーバーのアンインストールは、他のコンピューターやスマートフォンで信頼させた証明書を削除しません。**各閲覧デバイス上**で、フィンガープリントを確認した上でこのインストールのFlintEye CAまたは構成プロファイルのみを削除してください。[デバイスごとの証明書手順](LAN_ACCESS.ja.md#各閲覧デバイスで証明書を一度だけ信頼する)に従ってください。Windowsはアンインストーラーを通じて製品が所有するファイアウォールルールを削除します。手動で構成したLinux/macOSのファイアウォールまたはリバースプロキシのルールは、別途管理者がクリーンアップする必要があります。

## どのビルドにこの変更が含まれていますか？

Preview 10 には、これらの終了・削除の修正が含まれています。以前のインストーラーの動作は変わりません。**Information** で完全な版番号とソースコミットを確認してください。[M1 ビルドガイド](LOCAL_MACOS_BUILD.ja.md)では、GitHub Actions を使わずに現在コミットされているソースをビルドできます。

自動チェックでは、所有プロセスのクリーンアップ、子プロセスが生存している終了済みワーカー、Wine下でのWindowsジョブの所有権、およびインストールされたバンドルの停止要求をカバーしています。Wineは実際のWindowsのアンインストールテストの代わりにはなりません。ターゲットデバイスごとに終了、カメラの解放、再起動を確認し、関連のないアプリケーションが実行し続け、アンインストール後もアカウントと録画が保持されることを確認してください。

macOSでは、Dockからの通常の「終了」アクションもこの停止シーケンスを経由します。「強制終了」およびオペレーティングシステムの終了は別のケースであり、通常の「終了」パスがカメラの解放をテストする際に使用すべきパスです。


## 1.2.0 開発版の削除

Windowsの設定では、1つのインストールに対して重複削除を除外し、通常の記録完了を要求し、アンインストールデータのロックを確認してからアンインストーラーを実行するメンテナンスランチャーが使用されます。強制終了はデフォルトではありません。失敗した場合はデフォルトのデータフォルダーに診断ログを残し、安全な再試行を促します。他のプログラムのロックは、unins000.datを削除したり、無関係なプロセスを強制終了したりして解除してはなりません。報告されたError 32については、実機での再テストが必要です。製品が所有するファイアウォールルールは、明示的なUACの承認を得て削除されます。拒否された場合は削除が中断されるため、残留アクセスが隠蔽されることはありません。クライアント証明書の信頼関係は、各閲覧デバイス上で削除する必要があります。設定と記録はデフォルトで保持されます。明示的な削除はデフォルトのデータディレクトリのみを対象とします。[LANの信頼関係の削除](LAN_ACCESS.ja.md)
