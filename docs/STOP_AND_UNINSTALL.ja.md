# FlintEyeの停止とアンインストール

[English](STOP_AND_UNINSTALL.md) · [Documentation](README.ja.md) · [Installation](INSTALL.ja.md)

<a id="stop-monitoring"></a>
## モニタリングの停止

Windowsでは、FlintEyeの通知領域アイコン（隠れているアイコンの矢印を確認してください）から **Stop monitoring and quit** を選択します。macOSでは、FlintEyeのメニューバーアイコンを使用します。Linuxでは、FlintEyeのデスクトップウィンドウ内にあるボタンを使用します。ブラウザを閉じたりサインアウトしたりしても、表示セッションが終了するだけで、モニタリングは意図的にバックグラウンドで実行されたままになります。

更新されたアプリケーションは、終了する前にカメラワーカー、FFmpeg/FFprobeタスク、MediaMTX、およびAPIを停止します。シャットアウトではなく停止を行い、シャットダウン中の新しいワーカーの起動を防ぎ、ワーカーがすでに終了している場合でもその子プロセスをクリーンアップします。Windowsのメディア子プロセスは終了時killジョブによって所有されているため、アプリがクラッシュした場合でもそれらの子プロセスは終了します。他のアプリケーションによって起動されたブラウザやメディアツールはそのジョブの一部ではありません。

FlintEyeアイコンが消えていること、他のアプリが使用していなければカメラインジケータがオフになること、ローカルのFlintEye URLへの新しいリクエストが接続しなくなることを確認してください。サーバー停止後も、以前に開いたブラウザページがメモリ上に表示されたままになることがあります。FlintEyeを再起動すると、保存された設定と録画が復元されます。

<a id="windows-uninstall-the-application"></a>
## Windows: アプリケーションのアンインストール

**Settings → アプリ → インストールされているアプリ → FlintEye → アンインストール** の順に進みます。更新されたアンインストーラーは、まずインストールされているアプリに停止を要求して待機し、その後、現在のWindowsユーザーに属するその正確なインストールからの残存プロセスを確認します。プログラムファイルを削除する前に、残っているバンドルプロセスを停止します。それらが停止したことを確認できない場合は、Windowsを再起動してやり直せるように、エラーで削除が中断されます。

通常の場所は以下の通りです:

| 場所 | 内容 | 通常のアンインストール |
| --- | --- | --- |
| `%LOCALAPPDATA%\Programs\FlintEye` | アプリケーション、バンドルされたPython/FastAPI、FFmpeg、FFprobe、MediaMTX、およびアンインストーラー | 削除される |
| `%LOCALAPPDATA%\FlintEye` | アカウント、設定、ログ、録画インデックス、およびデフォルトの録画 | 保持される |
| 別途選択した録画フォルダ | Recordings | 保持される |

FastAPIはバンドルされたPythonアプリケーションの一部であり、デスクトップインストーラーによってインストールされる個別のWindowsサービスではありません。Python、FastAPI、またはFFmpegをグローバルにアンインストールする必要はありません。このインストールのWindowsログイン開始エントリとショートカットはアプリと一緒に削除されますが、別のインストールを指す登録は保持されます。ログイン時の自動起動は、サイレントインストーラーではなく、初回セットアップ後にデスクトップアプリによって登録されます。オプショナルなデータ削除の質問のデフォルトは **いいえ** です。サイレントアンインストールでは常にデータが保持されます。外部の録画フォルダがこのアンインストーラーによって削除されることはありません。

<a id="recover-an-older-windows-installation"></a>
## 以前のWindowsインストールの復元

古いインストーラーでは、ランチャーの終了後または削除後もバックグラウンドプロセスが実行し続ける可能性があります。それらのアンインストーラーには新しい停止手順が含まれていません。データフォルダを削除しても実行中のAPIは停止せず、設定や録画が破損する可能性があります。

1. アイコンがまだ存在する場合は、**Stop monitoring and quit** を試してください。
2. 停止しない場合は、Windowsを再起動してください。FlintEyeを再起動しないようにしてください。残存するログインエントリによって再び起動する場合は、**Settings → アプリ → スタートアップ** でFlintEyeのエントリを無効にしてから、再度再起動してください。
3. FlintEyeが「インストールされているアプリ」にまだ表示されている場合は、アンインストールします。表示されなくなっている場合は、エクスプローラーで `%LOCALAPPDATA%\Programs` を開き、残っている **FlintEye** プログラムフォルダのみを削除してください。データを明示的に消去したい場合を除き、`%LOCALAPPDATA%\FlintEye` は保持してください。
4. 準備ができたら、修正済みパッケージを再インストールしてください。保持したデータを再利用できます。

再起動せずに古いインストールを停止したい管理者向けに、更新されたソースには [stop_windows.ps1](../packaging/stop_windows.ps1) が含まれています。必要に応じてインストールフォルダを調整し、同じWindowsユーザーとしてレビュー済みのローカルスクリプトを実行してください:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\packaging\stop_windows.ps1 -InstallDir "$env:LOCALAPPDATA\Programs\FlintEye"
```

この呼び出しは、そのPowerShellプロセスに対してのみ実行ポリシーを変更します。ヘルパーは実行ファイルのパスと所有権を確認しますが、ファイルを削除しません。`--data-dir` の引数を検出し、選択されたインストール内の各カレントユーザーインスタンスに対して停止を要求します。1つのプロファイルのみを対象にするには、`-DataDir "C:\path\to\profile"` を追加します。これにより、環境変数を通じて選択されたプロファイルも処理されます。`-Force` がない場合、タイムアウトはエラーになります。タイムアウト後に一致するプロセスを強制終了する意図がある場合にのみ、`-Force` を使用してください。アンインストーラーは自身のインストールに対してその境界付きフォールバックを使用します。

選択されたデータディレクトリ内の `last-stop-result.json` （またはインストール全体を停止する場合は `%LOCALAPPDATA%\FlintEye` ）は、`already-stopped`、`requested-shutdown-completed`、`forced`、`incomplete` を区別します。終了コード0は選択されたプロセスが消滅したことを意味し、終了コード1は停止が不完全であったことを意味します。親の正常終了リクエストの成功は、進行中の録画がファイナライズされたことを証明するものではありません。Windowsは現在、メディアの子プロセスに対してプロセスツリーの終了を使用しています。録画中の停止をテストする場合は、最終的な録画と録画インデックスを確認してください。その後もAPIが応答する場合は、そのポートでリッスンしているプロセスを特定してください。別のインストール、手動で起動されたサーバー、Docker、またはキャッシュされたページである可能性があります。`python.exe` や `ffmpeg.exe` のプロセスを無差別に終了しないでください。

<a id="macos-and-linux"></a>
## macOSおよびLinux

macOSでは、`FlintEye.app` をゴミ箱に移動する前に、FlintEyeのメニューバーアイコンから **Disable start at login and quit** を選択してください。これにより、現在のインストール/プロファイルに属している場合に `~/Library/LaunchAgents/community.flinteye.plist` が削除され、そのログイン登録がアンロードされ、自動起動が無効になっていることが記憶されます。この明示的な操作により、共有バンドルIDのみを使用していた古いデフォルトプロファイルの登録も削除できます。自動起動は、そのあいまいなレガシーエントリを置き換えるものではありません。アプリをゴミ箱にドラッグするだけでは、アンインストーラーの実行やLaunchAgentの削除は行われません。

アプリがすでに停止している場合は、削除する前に次のコマンドを実行してください:

```sh
/Applications/FlintEye.app/Contents/MacOS/FlintEye --disable-autostart
```

別の場所にインストールされている場合はアプリのパスを調整し、カスタムプロファイルの場合は `--data-dir` を追加してください。このコマンドはログイン時の自動起動のみを変更します。実行中の別のインスタンスを停止したり、設定や録画を削除したりすることはありません。後でログイン自動起動を復元するには、`--enable-autostart` を指定して同じアプリを実行します。新しいMacの登録は特定のインストール済みアプリのコピーを対象としています。一時的なApp Translocationのパスは登録されないため、最初にアプリを「アプリケーション」フォルダに移動してください。別のインストール/プロファイルが所有する登録は保持され、有効化コマンドはそれを置き換える代わりに失敗を報告します。アプリがすでに削除されている場合は、上記のFlintEye LaunchAgentのみを削除し、ログアウトして再度ログインし、起動しなくなったことを確認してください。

Linuxでは、モニタリングを停止し、パッケージマネージャーを通じてパッケージを削除してください。データを意図的に消去したい場合を除き、[Recording lifecycle](DISTRIBUTION.ja.md#recording-lifecycle) にリストされているデータディレクトリは保持してください。手動で設定されたsystemdサービスやDockerコンテナは個別に管理されるため、独自のデプロイツールを通じて停止する必要があります。

<a id="which-builds-contain-this-change"></a>
## どのビルドにこの変更が含まれていますか？

これらの修正には、再ビルドされたインストーラーが必要です。以前にダウンロードしたインストーラーは変更されていません。ビルド情報内のソースコミットを確認してください。アプリケーションのバージョン単体ではこれらの変更を特定できません。[M1ビルドガイド](LOCAL_MACOS_BUILD.ja.md) は、GitHub Actionsなしで現在コミットされているソースをビルドします。

自動チェックでは、所有プロセスのクリーンアップ、子プロセスが生存している終了済みワーカー、Wine環境下でのWindowsジョブの所有権、およびインストールされたバンドルの正常終了リクエストをカバーしています。Wineは実際のWindowsアンインストールテストの代わりにはなりません。各ターゲットデバイスで終了、カメラの解放、および再起動を確認し、無関係なアプリケーションが実行され続けていること、およびアンインストールによってアカウントと録画が保持されることを確認してください。

macOSでは、Dockからの通常の「終了」アクションもこのシャットダウンシーケンスを経由します。「強制終了」およびオペレーティングシステムによる終了は別個のケースであり、カメラ解放をテストする際に使用すべきなのは通常の「終了」パスです。
