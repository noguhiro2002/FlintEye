# FlintEyeの停止とアンインストール

[English](STOP_AND_UNINSTALL.md) · [Documentation](README.ja.md) · [Installation](INSTALL.ja.md)

<a id="remove-by-installation-method"></a>
## インストール方法別の削除

**意図的に消去しない限り、アカウント、設定、録画は保持されます。** 1コマンドのインストーラーは、バイナリインストーラーと同じネイティブアプリケーションをインストールします。そのバンドルされたPython/FastAPI、FFmpeg、FFprobe、およびMediaMTXはアプリケーションと共に削除されます。他のソフトウェアで使用されているシステム全体のコピーは削除しないでください。

| インストール方法 | 停止と削除 |
| --- | --- |
| Windowsスクリプト / EXE / Actionsパッケージ | **Quit FlintEye** を選択し、**Settings → アプリ → インストールされているアプリ → FlintEye → アンインストール** を選択します。実行中の場合、アンインストーラーが自動的にシャットダウンを要求します。データ保持のデフォルト選択を維持してください。 |
| macOSスクリプト / Actions `install.sh` | メニューバーアイコン → **Disable start at login and quit** を選択します。Finderで **移動 → フォルダへ移動** を選択し、`~/Applications` と入力して、`FlintEye.app` をゴミ箱に移動します。存在する場合は、ロールバックで不要になった `FlintEye.previous.app` も削除してください。 |
| macOS DMGドラッグ＆ドロップ | 同様に終了アクションを行い、`/Applications/FlintEye.app` をゴミ箱に移動するか、選択したフォルダからアプリを削除します。不要になったらDMGを取り出し、ダウンロードしたDMGを削除してください。 |
| Linuxスクリプト / DEB / RPM | FlintEyeでログイン起動を無効にして終了し、`sudo apt-get remove flinteye` (DEB) または `sudo dnf remove flinteye` (RPM) を実行します。 |
| Docker Engine / 開発用Compose | デプロイフォルダで `docker compose down` を実行するか、ソースデプロイメントの場合は `docker compose -f deploy/compose.dev.yaml down` を実行します。データボリュームやバインドマウントされたデータは保持されます。 |
| Docker Desktop Compose | インストール時に使用したComposeファイルを使用します。チェックアウトから `docker compose -f deploy/compose.desktop.yaml down` を実行するか、そのファイルを個別にダウンロードした場合は `docker compose -f compose.desktop.yaml down` を実行します。 |
| systemd | `sudo systemctl disable --now flinteye` を実行します。その後、手動でインストールした `/etc/systemd/system/flinteye.service` を削除し、`sudo systemctl daemon-reload` を実行してから、上記のようにパッケージを削除します。`/var/lib/flinteye` と外部の録画フォルダは保持してください。ユーザーサービスの場合は、`systemctl --user` とその実際のユニット名および場所を使用してください。 |
| 手動ソース / 仮想環境 | フォアグラウンドプロセスを Ctrl+C で停止するか、設定したサービスを停止および無効化します。専用のチェックアウト/仮想環境を削除する前に、チェックアウト内の録画、`.env`、ランタイムJSON、およびその他のデータを保持してください。 |

`docker compose down` は名前付きボリュームを保持します。データを削除する意図がない限り、`--volumes` / `-v` を追加しないでください。ダウンロードしたインストーラーやActionsのZIPファイルも個別に削除可能です。`/Applications/FlintEye.app` と `~/Applications/FlintEye.app` の両方が存在する場合は、これらは別々のコピーです。アクティブな方を終了し、不要になった各コピーを削除してください。検証中に古いコピーを起動しないように注意してください。

<a id="stop-monitoring-and-quit"></a>
## Stop monitoring and quit

完全に終了するには、WindowsではFlintEyeの通知領域アイコン（隠しアイコンの矢印をご確認ください）から **Quit FlintEye** を選択します。macOSではFlintEyeのメニューバーアイコンを使用します。LinuxではコンパクトなFlintEyeコントロールウィンドウを使用します。**Stop monitoring** は設定とAPIを利用可能な状態にしたままカメラや録画を一時停止し、**Start monitoring** で再開します。[ステータスカラー、録画のファイナライズ、および起動時の設定](MONITORING.ja.md)。ブラウザを閉じたりサインアウトしたりしても、閲覧セッションが閉じるだけであり、意図的にモニタリングは実行されたままになります。

更新されたアプリケーションは、終了する前にカメラワーカー、FFmpeg/FFprobeタスク、MediaMTX、およびAPIを停止します。停止中の新しいワーカーの起動を防ぎ、ワーカーがすでに終了している場合でも子プロセスをクリーンアップします。Windowsのメディアの子プロセスは終了時killジョブによって所有されているため、アプリがクラッシュした場合でもそれらの子プロセスは終了します。他のアプリケーションによって起動されたブラウザやメディアツールはそのジョブの一部ではありません。

FlintEyeアイコンが消え、他のアプリが使用していなければカメラインジケータが消灯し、ローカルのFlintEye URLへの新規リクエストが接続されなくなることを確認してください。サーバー停止後も、以前に開いたブラウザページがメモリから表示されたままになる場合があります。FlintEyeを再起動すると、保存された設定と録画が復元されます。

<a id="windows-uninstall-the-application"></a>
## Windows: アプリケーションのアンインストール

**Settings → アプリ → インストールされているアプリ → FlintEye → アンインストール**を使用します。更新されたアンインストーラーは、まずインストールされたアプリに停止を要求して待機し、その後、現在のWindowsユーザーに属するその正確なインストールからの残存プロセスを確認します。プログラムファイルを削除する前に、残っているバンドルされたプロセスを停止します。停止したことを確認できない場合は、Windowsを再起動して再試行できるようにエラーで削除が中断されます。

通常の保存場所は次のとおりです。

| 場所 | 内容 | 通常のアンインストール |
| --- | --- | --- |
| `%LOCALAPPDATA%\Programs\FlintEye` | アプリケーション、バンドルされたPython/FastAPI、FFmpeg、FFprobe、MediaMTX、およびアンインストーラー | 削除されます |
| `%LOCALAPPDATA%\FlintEye` | アカウント、設定、ログ、録画インデックス、およびデフォルトの録画 | 保持されます |
| 別途選択した録画フォルダ | Recordings | 保持されます |

FastAPIはバンドルされたPythonアプリケーションの一部であり、デスクトップインストーラーによってインストールされる個別のWindowsサービスではありません。Python、FastAPI、またはFFmpegをグローバルにアンインストールする必要はありません。このインストールのWindowsのログイン起動エントリとショートカットはアプリと共に削除されますが、別のインストールを指す登録は保持されます。ログイン時の起動は、サイレントインストーラーではなく、最初のセットアップ後にデスクトップアプリによって登録されます。オプションのデータ削除の質問のデフォルトは**いいえ**であり、サイレントアンインストールでは常にデータが保持されます。外部の録画フォルダがこのアンインストーラーによって削除されることはありません。

<a id="recover-an-older-windows-installation"></a>
## 以前のWindowsインストールの修復

古いインストーラーでは、ランチャーの終了後や削除後もバックグラウンドプロセスが実行し続ける可能性があります。それらのアンインストーラーには新しい停止手順が含まれていません。データフォルダを削除しても実行中のAPIは停止せず、設定や録画が破損する可能性があります。

1. アイコンがまだ存在する場合は、**Stop monitoring and quit** を試してください。
2. 停止しない場合は、Windowsを再起動します。FlintEyeの再開は避けてください。残存しているログインエントリによって再度起動された場合は、**Settings → アプリ → スタートアップ**でFlintEyeのエントリを無効にしてから、再度再起動してください。
3. FlintEyeが「インストールされているアプリ」にまだ表示されている場合は、アンインストールします。表示されなくなっている場合は、エクスプローラーで `%LOCALAPPDATA%\Programs` を開き、残っている **FlintEye** プログラムフォルダのみを削除してください。データを明示的に消去したい場合を除き、`%LOCALAPPDATA%\FlintEye` は保持してください。
4. 準備ができたら、修正されたパッケージを再インストールします。保持されたデータは再利用できます。

再起動せずに古いインストールを停止したい管理者のために、更新されたソースには [stop_windows.ps1](../packaging/stop_windows.ps1) が含まれています。レビュー済みのローカルスクリプトを同じWindowsユーザーとして実行し、必要に応じてインストールフォルダを調整してください。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\packaging\stop_windows.ps1 -InstallDir "$env:LOCALAPPDATA\Programs\FlintEye"
```

この呼び出しは、そのPowerShellプロセスに対してのみ実行ポリシーを変更します。ヘルパーは実行ファイルのパスと所有権を確認しますが、ファイルの削除は行いません。`--data-dir` 引数を検出し、選択されたインストール内の各カレントユーザーインスタンスに対して正常終了を要求します。1つのプロファイルを対象にするには、`-DataDir "C:\path\to\profile"` を追加します。これにより、環境変数を通じて選択されたプロファイルも処理されます。`-Force` がない場合、タイムアウトはエラーになります。タイムアウト後に一致するプロセスを強制終了する意図がある場合にのみ、`-Force` を使用してください。アンインストーラーは、独自のインストールに対してその制限付きフォールバックを使用します。

選択されたデータディレクトリ内の `last-stop-result.json`（またはインストール全体での停止の場合は `%LOCALAPPDATA%\FlintEye`）は、`already-stopped`、`requested-shutdown-completed`、`forced`、および `incomplete` を区別します。終了コード0は選択されたプロセスが消えたことを意味し、終了コード1は停止が不完全であったことを意味します。別の `last-monitoring-stop.json` 確認記録には、録画の完了と保留中/強制終了の結果が記録されます。Windowsヘルパーは、停止要求後に作成された確認記録を `media_finalization` レポートに組み込みます。見つからない確認記録や古い確認記録は検証されないままになります。プロセスの終了単体では録画の完了を証明しません。録画中の停止をテストする際は、最後の録画と録画インデックスを確認してください。その後もAPIが応答する場合は、そのポートでリッスンしているプロセスを特定してください。それは別のインストール、手動で起動されたサーバー、Docker、またはキャッシュされたページである可能性があります。`python.exe` や `ffmpeg.exe` のプロセスを無差別に終了させないでください。

<a id="macos-and-linux"></a>
## macOSとLinux

macOSでは、`FlintEye.app` をゴミ箱に移動する前に、FlintEyeのメニューバーアイコンから **Disable start at login and quit** を選択してください。これにより、現在のインストール/プロファイルに属している場合に `~/Library/LaunchAgents/community.flinteye.plist` が削除され、そのログイン登録が解除され、自動起動が無効になっていることが記憶されます。この明示的な操作により、共有バンドルIDのみを使用していた古いデフォルトプロファイルの登録を削除することもできます。自動起動は、そのあいまいなレガシーエントリを置き換えるものではありません。アプリをゴミ箱にドラッグするだけでは、アンインストーラーは実行されず、LaunchAgentも削除されません。

アプリがすでに停止している場合は、削除する前に次のコマンドを実行してください。

```sh
/Applications/FlintEye.app/Contents/MacOS/FlintEye --disable-autostart
```

別の場所にインストールされている場合はアプリのパスを調整し、カスタムプロファイルの場合は `--data-dir` を追加してください。このコマンドはログイン時の起動のみを変更するものであり、実行中の別のインスタンスを停止したり、設定や録画を削除したりするものではありません。後でログイン時の起動を復元するには、同じアプリを `--enable-autostart` 付きで実行します。新しいMacの登録は、インストールされた特定のアプリのコピーを対象とします。一時的なApp Translocationのパスは登録されないため、最初にアプリを「アプリケーション」フォルダに移動してください。別のインストール/プロファイルが所有する登録は保持され、有効化コマンドは置き換える代わりに失敗を報告します。アプリがすでに削除されている場合は、上記のFlintEye LaunchAgentのみを削除してから、ログアウトして再度ログインし、起動しなくなったことを確認してください。

Linuxでは、モニタリングを停止し、パッケージマネージャーを通じてパッケージを削除してください。データを意図的に消去したい場合を除き、[Recording lifecycle](DISTRIBUTION.ja.md#recording-lifecycle) にリストされているデータディレクトリは保持してください。手動で設定されたsystemdサービスやDockerコンテナーは個別に管理され、独自のデプロイメントツールを通じて停止する必要があります。

<a id="which-builds-contain-this-change"></a>
## どのビルドにこの変更が含まれていますか？

これらの修正には、再ビルドされたインストーラーが必要です。以前にダウンロードしたインストーラーは変更されていません。ビルド情報のソースコミットを確認してください。アプリケーションのバージョンだけではこれらの変更を識別できません。[M1ビルドガイド](LOCAL_MACOS_BUILD.ja.md) は、GitHub Actionsなしで現在コミットされているソースをビルドします。

自動チェックでは、所有プロセスのクリーンアップ、子プロセスが生存している終了済みワーカー、Wine下でのWindowsジョブの所有権、およびインストールされたバンドルの停止要求をカバーしています。Wineは実際のWindowsのアンインストールテストの代わりにはなりません。ターゲットデバイスごとに終了、カメラの解放、再起動を確認し、関連のないアプリケーションが実行し続け、アンインストール後もアカウントと録画が保持されることを確認してください。

macOSでは、Dockからの通常の「終了」アクションもこの停止シーケンスを経由します。「強制終了」およびオペレーティングシステムの終了は別のケースであり、通常の「終了」パスがカメラの解放をテストする際に使用すべきパスです。


## 1.2.0 開発版の削除

Windowsの設定では、1つのインストールに対して重複削除を除外し、通常の記録完了を要求し、アンインストールデータのロックを確認してからアンインストーラーを実行するメンテナンスランチャーが使用されます。強制終了はデフォルトではありません。失敗した場合はデフォルトのデータフォルダーに診断ログを残し、安全な再試行を促します。他のプログラムのロックは、unins000.datを削除したり、無関係なプロセスを強制終了したりして解除してはなりません。報告されたError 32については、実機での再テストが必要です。製品が所有するファイアウォールルールは、明示的なUACの承認を得て削除されます。拒否された場合は削除が中断されるため、残留アクセスが隠蔽されることはありません。クライアント証明書の信頼関係は、各閲覧デバイス上で削除する必要があります。設定と記録はデフォルトで保持されます。明示的な削除はデフォルトのデータディレクトリのみを対象とします。[LANの信頼関係の削除](LAN_ACCESS.ja.md)
