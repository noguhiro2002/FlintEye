# FlintEye Environment Options

[日本語](ENV_OPTIONS.ja.md)

[Documentation](../README.md)

> These are low-level source/development commands, run from the repository root.
> Keep listeners on loopback; LAN access uses the authenticated HTTPS proxy described in the [distribution guide](../DISTRIBUTION.md).

This document lists the environment variables currently read by the codebase.
It is based on:

- `flinteye_app/orchestrator_store.py`
- `flinteye_app/workers/uvc_to_rtsp.py`
- `flinteye_app/workers/multiview_to_rtsp.py`
- `flinteye_app/orchestrator_models.py`
- `flinteye_app/orchestrator_supervisor.py`
- `flinteye_app/orchestrator_api.py`

## Common rules

- Boolean values accepted by the parsers:
  - true: `1`, `true`, `yes`, `on`
  - false: `0`, `false`, `no`, `off`
- CSV-style lists accept commas, semicolons, or newlines.
- Empty values usually mean "unset / no override", but some fields must stay non-empty once enabled.

## Important caveats

- `MTX_CONTROL_MODE`
  - Schema values: `windows_service`, `systemd`, `launchd`, `direct`, `external`, `docker_compose`
  - Actually implemented by `OrchestratorSupervisor`: `windows_service`, `systemd`, `launchd`, `direct`, `external`
  - `docker_compose` is present in the model but is not implemented by the supervisor yet.
- `AUTH_PROVIDER`
  - Schema values: `local`, `legacy_token`, `oidc`
  - Actually usable today: `local`, `legacy_token`
  - `oidc` exists in the model, but the API currently returns `501` for OIDC auth flow.
- `UVC_LATENCY_PRESET`
  - `flinteye_app/workers/uvc_to_rtsp.py` currently accepts only `low`
  - To get normal/default behavior, leave it unset
  - `normal` is mentioned in README, but the current UVC parser does not accept it

## API / auth

- `API_HOST`
  - Any host or IP string

- `API_PORT`

## Web UI / Vite dev server

- `WEBUI_HOST`
  - Any host or IP string
  - Used by `tools/start_orchestrator_stack.py` for the Vite dev server bind host
- `WEBUI_PORT`
  - Integer `1..65535`
  - Used by `tools/start_orchestrator_stack.py` for the Vite dev server bind port
- `WEBUI_API_PROXY_TARGET`
  - Optional HTTP origin for the Vite `/api/*` dev proxy
  - Example: `http://127.0.0.1:18080`
  - If unset, `tools/start_orchestrator_stack.py` derives it from `API_PORT`
- `WEBUI_MTX_API_PROXY_TARGET`
  - Optional HTTP origin for the Vite `/v3/*` dev proxy
  - Example: `http://127.0.0.1:9997`
  - If unset, `tools/start_orchestrator_stack.py` defaults it to `http://127.0.0.1:9997`
- `VITE_API_PROXY_TARGET`
  - Environment variable read directly by `frontend/vite.config.*`
  - Usually injected by `tools/start_orchestrator_stack.py`
  - Use this for manual `npm run dev` starts when you need a non-default API proxy target
- `VITE_MTX_API_PROXY_TARGET`

  - Use this for manual `npm run dev` starts when you need a non-default MediaMTX API proxy target
- `VITE_API_BASE`

  - Example: `http://127.0.0.1:8889`

  - Boolean
  - Enables REST-side management of MediaMTX `global` / `paths` data
- `MTX_CONFIG_PATH`
  - Path to `mediamtx.yml`

## IP camera ingest

- `MTX_IP_PATHS`
  - CSV list of MediaMTX path names
  - Example: `ipcam1,ipcam2`
- `MTX_IP_<TOKEN>_SOURCE`
  - Source RTSP URL for that IP camera
- `MTX_IP_<TOKEN>_ENABLED`
  - Boolean

The Settings > IP Cameras screen adds per-camera runtime settings that are stored in
`runtime.json` rather than environment variables:

- `timestamp_mode`
  - `auto`: measure the live RTSP timestamps at relay startup and select `source`,
    `wallclock`, or `cfr`
  - `source`: preserve timestamps supplied by the camera
  - `wallclock`: replace unreliable camera timestamps without re-encoding
  - `cfr`: generate a fixed frame rate and re-encode with libx264
- `cfr_fps`
  - Target frame rate used when `timestamp_mode` resolves to `cfr`
- `onvif_mode`
  - `auto`: use WS-Discovery and match the Source URL host. If discovery fails, try
    common HTTP(S) ports on the camera, including TCP 2020 for Tapo.
  - `manual`: use the complete configured ONVIF Device Service URL, including a
    non-default port or path when required
  - `disabled`: skip ONVIF inspection and only measure RTSP timing
- `onvif_address`, `onvif_username`, `onvif_password`
  - Optional manual ONVIF connection settings. Source URL credentials are used when
    separate ONVIF credentials are not supplied.

The **Inspect camera** action reports device/firmware information, media profiles,
observed frame rate, timestamp reversals, large gaps, and the recommended timestamp mode.
ONVIF capability handling is manufacturer- and model-independent: advertised service
XAddrs are honored, Media2 is preferred when available, Media1 is used as a fallback,
and a partial or absent ONVIF implementation does not disable RTSP timing inspection.

Example:

- `MTX_IP_PATHS=ipcam1`
- `MTX_IP_IPCAM1_SOURCE=rtsp://user:pass@192.168.1.50:554/stream1`
- `MTX_IP_IPCAM1_ENABLED=true`

## Multiview

- `MV_ENABLED`
  - Boolean
- `MV_SOURCE_MODE`
  - `env`
  - `api`
  - `hybrid`
- `MV_SOURCE_PATHS`
  - CSV list of source stream paths
- `MV_AUTO_PLACEHOLDER_MISSING_SOURCES`
  - `true`
  - `false`
  - When `true`, configured sources missing from MediaMTX are rendered as `No Stream` tiles instead of failing the whole multiview output.
- `MV_MTX_API_URL`
  - URL to the MediaMTX path-list API
- `MV_INPUT_RTSP_BASE_URL`
  - RTSP base URL for source streams
- `MV_OUTPUT_RTSP_BASE_URL`
  - RTSP base URL for generated multiview streams
- `MV_OUTPUT_PREFIX`
  - Any non-empty string
  - Example: `multiview`
- `MV_MAX_SOURCES`
  - Integer `2..32`
- `MV_TILE_COUNT`
  - Integer `2..32`
- `MV_CANVAS_WIDTH`
  - Positive integer
- `MV_CANVAS_HEIGHT`
  - Positive integer
- `MV_GRID_COLUMNS`
  - Positive integer
  - Or leave unset for automatic grid width
- `MV_SLOT_POSITIONS`
  - Semicolon-separated `x,y,w,h` entries
  - Example: `0,0,960,540;960,0,960,540;0,540,960,540;960,540,960,540`
- `MV_VIEW_<N>_SLOT_POSITIONS`
  - Per-view slot overrides in the same `x,y,w,h;...` format
  - Example: `MV_VIEW_1_SLOT_POSITIONS=0,0,1920,1080`
- `MV_FPS`
  - Positive integer
- `MV_LATENCY_PRESET`
  - `low`
  - `normal`
- `MV_ENCODER`
  - `auto`
  - Or any ffmpeg H.264 encoder available in your build
- `MV_QUALITY_PRESET`
  - `high`
  - `standard`
  - `low`
- `MV_BITRATE`
  - ffmpeg bitrate string
- `MV_MAXRATE`
  - ffmpeg maxrate string
- `MV_BUFSIZE`
  - ffmpeg bufsize string
- `MV_GOP`
  - Positive integer
- `MV_BFRAMES`
  - Integer `>= 0`
- `MV_X264_PRESET`
  - libx264 preset string
  - Common values:
    - `ultrafast`
    - `superfast`
    - `veryfast`
    - `faster`
    - `fast`
    - `medium`
    - `slow`
    - `slower`
    - `veryslow`
- `MV_RESTART_BACKOFF_SEC`
  - Number `>= 0`
- `MV_INPUT_STALL_TIMEOUT_SEC`
  - Number `>= 0`
  - Seconds before a non-responsive RTSP input is treated as stalled by FFmpeg
  - `0` disables this timeout
- `MV_INPUT_STALL_TIMEOUT_OPTION`
  - `auto`
  - `rw_timeout`
  - `stimeout`
  - `timeout`
  - `none`
  - Use `auto` unless a specific FFmpeg build needs a fixed option
- `MV_INPUT_THREAD_QUEUE_SIZE`
  - Positive integer; default `128` in normal mode and capped at `32` in low-latency mode
- `MV_INPUT_HEALTHCHECK_ENABLED`
  - Boolean; monitors every expected MediaMTX path, RTSP reader and byte progression
- `MV_INPUT_HEALTHCHECK_INTERVAL_SEC`
  - Positive number; default `5`
- `MV_INPUT_ISOLATION_THRESHOLD`
  - Positive integer; default `3`
  - Repeated failures replace only the affected tile with `No Stream`
- `MV_INPUT_RETRY_INTERVAL_SEC`
  - Positive number; default `30`
- `MV_STATUS_FILE`
  - Ephemeral JSON status path; default `./logs/runtime/multiview_status.json`
- `MV_FFMPEG_BIN`
  - Executable path or command name
- `MV_LOGLEVEL`
  - ffmpeg log level string
  - Common values: `error`, `warning`, `info`, `debug`
- `MV_DRY_RUN`
  - Boolean
- `MV_ONCE`
  - Boolean
- `MV_VERBOSE`
  - Boolean
- `MV_MAINTENANCE_ENABLED`
  - Boolean
- `MV_MAINTENANCE_RESTART_INTERVAL_SEC`
  - Number `> 0`
- `MV_MAINTENANCE_ALIGN_WITH_RECORD_SEGMENTS`
  - Boolean
- `MV_MAINTENANCE_RESTART_OFFSET_SEC`
  - Number `>= 0`
