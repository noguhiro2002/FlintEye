# M1 Mac でテスト用 DMG をビルドする

[English](LOCAL_MACOS_BUILD.md) · [Documentation](README.ja.md) · [Build and release](RELEASING.ja.md)

この手順は、GitHub Actions のビルド時間を消費せずに、Apple Silicon Mac 上で現在コミットされているソースをビルドします。これには、MediaMTX のパス修正、統合された設定画面、および **FlintEye API** のドキュメントタイトルが含まれます。FFmpeg、FFprobe、および MediaMTX は自動的にビルドおよびバンドルされます。FlintEye 用に個別のコピーをインストールする必要はありません。

結果はローカルのテストビルドになります。アップロード、公開、アプリケーションフォルダへのインストール、既存の FlintEye データの変更などは一切行われません。既存の GitHub インストーラーは変更されません。この手順はご自身の Mac を対象としており、サポートされているすべての macOS バージョンとの互換性を確立するものではありません。

<a id="1-prepare-the-mac-once"></a>
## 1. Mac の事前準備を 1 回行う

Mac 本体で **Rosetta を使用して開く** を無効にしたターミナルを使用します。電源を接続し、ソースアーカイブ、メディアのコンパイル、Python パッケージ、DMG 用に十分な空き容量を確保してください。最初に約 15〜20 GB の作業領域が必要です。ビルド時間は Mac とネットワーク環境に依存するため、初回実行には時間がかかる場合があります。

Apple のコマンドライン開発者ツールをインストールし、インストールが完了するのを待ちます：

```sh
xcode-select --install
```

すでにインストールされている場合は、そのまま進めてください。`/opt/homebrew/bin/brew` が存在しない場合は、[公式手順](https://docs.brew.sh/Installation)に従ってネイティブの Apple Silicon 版 Homebrew をインストールします。次に、ビルドツールをインストールします：

```sh
/opt/homebrew/bin/brew install python@3.14 python-tk@3.14 node@22 go cmake pkgconf ninja gh
```

Python 3.14.10 以降の 3.14 パッチバージョン、Node.js 22.12 以降の 22.x、および Go 1.27 以降を使用してください。このスクリプトは、シェルでアクティブな Conda 環境がある場合でも、ネイティブの Homebrew ツールを明示的に選択します。独自の Python 環境を作成します。Homebrew は [Python 3.14 用の Tk を個別に提供しています](https://formulae.brew.sh/formula/python-tk@3.14)。Tk はパスワードおよびフォルダウィンドウに必要です。[Node.js 22](https://formulae.brew.sh/formula/node@22) は既存のビルドワークフローと一致しており、ピン留めされた MediaMTX ソースには [Go 1.27 以降](https://formulae.brew.sh/formula/go)が必要です。

<a id="2-get-the-updated-source"></a>
## 2. 更新されたソースを取得する

パブリックソースの専用チェックアウトを作成します。GitHub ログインは必要ありません。スペースを含まないパスを選択してください。以前のプライベートリポジトリを使用していた場合は、関連のない履歴をプルするのではなく、新しいディレクトリにクローンしてください。

```sh
mkdir -p ~/Developer
cd ~/Developer
git clone https://github.com/noguhiro2002/FlintEye.git FlintEye-build
cd FlintEye-build
```

以降のビルドでは、再度クローンする代わりに、そのチェックアウトを更新します：

```sh
cd ~/Developer/FlintEye-build
git switch main
git pull --ff-only
```

このチェックアウトはクリーンに保ってください。ヘルパーは現在のコミットの新しいスナップショットをビルドするため、コミットされていないソースの変更がある場合は停止します。無視された録画、ランタイム設定、古いビルドディレクトリ、依存関係フォルダはスナップショットにコピーされません。

<a id="3-build-and-automatically-verify-the-dmg"></a>
## 3. DMG のビルドと自動検証

メニューバーアイコンから **監視を停止して終了** を使用して、実行中の FlintEye をすべて終了します。また、ポート 8554、8889、9997、または UDP 8189 を使用している個別の MediaMTX インスタンスも停止してください。ブラウザを閉じるだけでは監視は停止しません。

最初にツールを確認します：

```sh
/opt/homebrew/opt/python@3.14/bin/python3.14 packaging/build_macos_local.py --check-only
```

次にビルドを実行します。`caffeinate` はこのコマンドの実行中に Mac がスリープ状態になるのを防ぎます。蓋を開けたままにしてください：

```sh
caffeinate -i /opt/homebrew/opt/python@3.14/bin/python3.14 packaging/build_macos_local.py
```

ヘルパーは、M1 MacBook Air の場合、デフォルトで 2 つのコンパイルジョブを使用します。メモリが不足している場合は、`--jobs 1` を指定して再実行してください。試行ごとに `dist/local-macos/` の下に独自のディレクトリが作成されるため、再試行しても以前のビルドが上書きされることはありません。

次の手順が順番に実行されます：

1. コミットされたソースを新しいビルドディレクトリに展開し、制約された Python 依存関係を別の環境にインストールします。
2. MediaMTX の起動回帰テストを実行し、ピン留めされたメディアツールをコンパイルし、認証されたメディア入力をテストします。
3. 共有 Web インターフェイスを再ビルドし、Python およびメディアツールとともに ARM64 アプリおよび DMG にパッケージ化します。通常のビルドと同じローカルアドホック署名を適用します。Apple デベロッパアカウントは必要ありません。
4. DMG をマウントし、`codesign --verify --deep --strict` で最終アプリを検証し、内部リンクを保持したままアプリをコピーし、DMG を取り出します。コピーしたアプリを検証し、意図的に変更されたコピーが復元前に検証に失敗することを証明します。Gatekeeper の評価を個別に記録します。アドホック署名は、Developer ID の信頼や公証を意味するものではありません。その後、セットアップとメディアをテストします。セットアップ、認証、ワーカーの読み込み、MediaMTX、合成録画、および再生ダウンロードを確認します。
5. そのテストアプリを別のディレクトリに移動し、同じ一時プロファイルで再起動します。これにより、macOS の起動失敗に対処する保存済みパスの修復がチェックされます。

自動テストでは、一時アカウントと生成されたビデオを使用します。カメラを開いたり、保存されたパスワードを使用したり、既存の録画を変更したりすることはありません。

成功すると、**Local DMG verified:** と正確なファイルパスが表示されます。そのビルドディレクトリの下にある `artifacts` フォルダを開きます。ここには以下が含まれています：

- `FlintEye-VERSION-local-<commit>-macos-arm64.dmg`
- 対応するメディアソースとライセンス
- `vendor-sha256.json`、`build-info.json`、`-signature.json` の整合性/Gatekeeper レポート、および `SHA256SUMS`

アプリケーションは選択されたソースからの数値バージョンを報告し、ファイル名とビルド情報は新しいソースコミットを識別します。これは既存の的リリースを置き換えるものではありません。ファイルの整合性を確認するには、`artifacts` フォルダでターミナルを開き、以下を実行します：

```sh
shasum -a 256 -c SHA256SUMS
```

ステップが失敗した場合、ヘルパーは停止し、作業ディレクトリを表示します。障害を報告する際は、その `build.log` を保持してください。テスト失敗後に `source/dist` の中に残された DMG は、検証された結果ではありません。ヘルパーを再実行すると、新規ビルドが開始されます。ソースのダウンロードでは、HTTPS 証明書とチェックサムの検証が維持されます。

<a id="4-install-and-check-your-existing-setup"></a>
## 4. 既存のセットアップをインストールして確認する

1. 古い FlintEye が停止していることを確認します。新しく検証された DMG を開き、`/Applications/FlintEye.app` を完全なアプリに置き換え、DMG を取り出します。インストールされたアプリを開きます。`~/Library/Application Support/FlintEye` を削除しないでください。
2. 既存の管理者パスワードでサインインします。カメラと録画設定が保持されていることを確認します。macOS から確認を求められた場合は、[インストールガイド](INSTALL.ja.md)に記載されているアプリ固有の **プライバシーとセキュリティ → このまま開く** アクションを使用します。
3. MediaMTX が起動し、**ライブビュー**に映像が表示されることを確認します。古く保存された `AppTranslocation` の実行ファイルパスは自動的に修復されるはずです。カメラがオン/オフを繰り返さなくなったことを確認してから、短いクリップを録画および再生します。
4. **設定** を開きます。個別の **録画ストレージとビューアーアクセス** パネルはなくなっているはずです。フォルダ、クォータ、保持期間には **録画** を、ビューアーパスワードには **ランタイムとアクセス** を、アップデートの確認には **一般** を使用してください。録画の変更を保存するには **変更を保存** を使用します。タイトル **FlintEye API** について `/docs` および `/redoc` を確認します。
5. アプリを終了して再度開き、ログイン時の自動起動を個別に確認します。これらの物理カメラおよびデスクトップのチェックは、自動ビルド結果とは明確に区別してください。

それでもビデオが機能しない場合は、`~/Library/Application Support/FlintEye/logs/` 配下の `orchestrator.log` および `mediamtx.log` を検査してください。起動パスが修正されても、カメラの権限、ポートの競合、またはキャプチャフォーマットの問題が除外されるわけではありません。

<a id="the-same-settings-design-on-other-installations"></a>
## その他のインストールにおける同じ設定デザイン

Windows、macOS、Linux パッケージ、Docker、およびソースインストールでは、同じ `frontend/src` インターフェイスが使用されます。古い過度に大きなパネルは、すべてのプラットフォームでそこから削除されています。ネイティブバンドルビルダーと Docker ビルダーの両方が、ソースからそのインターフェイスを再ビルドします。

すでにダウンロードされたインストーラーやすでにビルドされた Docker イメージは、古いインターフェイスを保持します。変更を反映するには、対応するプラットフォームのパッケージを再ビルドしてインストールするか、コンテナを再ビルドしてください。古いインストーラーを再度開いても、埋め込まれた画面を更新することはできません。この M1 手順では ARM64 macOS DMG のみが作成されます。Windows および Linux のビルドでは、それぞれの[ネイティブビルド手順](RELEASING.ja.md#local-native-build)を使用します。

現在の Windows ソースでは、エラー出力を保持したまま、カメラ検出、サムネイル更新、およびその他のバックグラウンドメディアプロセスのコンソールウィンドウも抑制されます。その修正には新しくビルドされた Windows インストーラーが必要です。既存の `.exe` のダウンロードを変更するものではありません。

現在のソースには、[完全なシャットダウンおよびアンインストールの修正](STOP_AND_UNINSTALL.ja.md)も含まれています。インストール済みバンドルのテストでは、シャットダウンを要求し、API および MediaMTX のリッスンポートが閉じられることを確認します。Mac ではさらに、カメラのストリーミング中に **監視を停止して終了** を選択し、インジケーターがオフになりアイコンが消えることを確認してから、FlintEye を再度開き、保存された設定が引き続き機能することを確認してください。

ローカルの M1 ビルドでは、ネイティブの AppKit 終了デリゲートテストも実行されます。インストール後、カメラのストリーミング中に、メニューバーの停止アクションと Dock からの通常の終了アクションの両方をテストしてください。これらの物理デバイスのチェックは引き続き必要です。
